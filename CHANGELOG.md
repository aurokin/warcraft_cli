# Changelog

All notable changes to this repo are recorded here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The workspace ships under a single version — every `pyproject.toml` in the monorepo bumps together.

Add user-visible changes to `[Unreleased]` in the same PR that ships them. See [docs/RELEASE.md](docs/RELEASE.md) for the release flow.

## [Unreleased]

### Added

- CI and release checks install the root wheel outside the checkout and verify all console scripts, schema output, package origins, and bundled Icy Veins discovery data.

### Changed

- Guide comparisons write new exports under `bundles/<generation>/<provider>` and publish their relative paths atomically in the root manifest. Follow `manifest.providers[].bundle_path`; earlier exports remain available after a refresh.
- Composed guide exports call provider services directly, without capturing console output. Warcraft Logs discovery and readiness also use services independent of the CLI module.

### Fixed

- A failed guide comparison refresh cannot overwrite bundles from a previous completed comparison. Reuse verifies the saved bundle identity and refreshes altered or corrupt bundles.
- SimC APL comparison and validation reject output paths that collide with any input or another output before writing, including JSON reports, symlinks, hardlinks, and case aliases.
- Static SimC APL analysis honors `actions=` replacement, empty resets, inline `/` action separators, and dispatch options in any order. Branch filtering distinguishes actions sharing a source line.
- Raidbots input summaries and talent handoffs honor the last assignments within the first actor's scope, including combined and split talent overrides; global settings retain their final values.
- Warcraft Logs guild report listing accepts canonical and localized realm names through the same fallback as character and guild reads.
- Warcraft Logs sampled pull deduplication keeps different keystone levels and contradictory rosters separate, and shares roster reads with spec filtering. Non-object OAuth token responses fail as invalid responses.
- Raider.IO samples pin the first resolved season for later pages and reject inconsistent or unidentified seasons instead of mixing cohorts.
- Wowhead linked graphs preserve edges between retained nodes at the node limit. Every full-comment citation anchor has a corresponding source.
- Provider cache defaults follow the current runtime roots when settings load. Missing-credential end-to-end tests run outside repository dotenv discovery, and pip deployment resolves the repository from any caller directory.

## [0.6.0] - 2026-10-04

This release standardizes every binary's JSON, errors and global output flags, expands provider
reads and guide discovery, and corrects build and sampled-analysis results.

**Breaking migration:** read payloads from `data`, use `--brief` after wrapper `search`/`resolve`
and global output flags before the subcommand, and update renamed fields and removed commands
listed below. Regenerate existing SimC build harnesses and rerun their comparisons: earlier
harnesses could replace the supplied build with the spec's default talents.

### Added

- Every binary emits one envelope with `ok`, `provider`, `command`, `kind`, `schema_version: "1"`, `query`, `provenance` and `data`, plus `error` on failure. `warcraft schema` exposes the shared schema. Commands, arguments and options have help text and generated references, including option bounds and metavars.
- Global `--compact`, `--compact-max-chars`, `--fields`, `--fields-strict` and `--profile agent|human` work on every binary and wrapper passthrough. Compact output preserves URLs, talent strings, export codes, SimC profiles and command/input values, and lists every cut in `provenance.compacted_paths`. Missing projected paths appear in `fields_missing`; strict projection fails `missing_fields`. Failure envelopes stay whole.
- Provider tiers appear in `warcraft doctor`: core Wowhead, Warcraft Logs and SimC; supported Method, Icy Veins, Raider.IO, Warcraft Wiki and Lorrgs; experimental Raidbots, Blizzard and CurseForge. Lorrgs moves from experimental to supported.
- Release-tag CI runs `make check`, builds the root wheel and attaches it to the GitHub release for `pipx` and `uvx` installation.
- `blizzard pvp-season`, `pvp-leaderboard` and `pvp-character` read season metadata, title cutoffs, ranked players and character ratings/records. Leaderboards support `--season` and `--limit` up to 5000; PvP supports retail, progression Classic and Anniversary; Classic character reads probe 2v2, 3v3, 5v5 and rbg when the summary omits them. Classic Era has no PvP seasons.
- `blizzard collections` returns mounts, pets, toys, heirlooms and transmogs with counts, name filters and limits. `auctions <realm>` and retail `commodities` summarize listings and units per item id with minimum and unit-weighted median prices in copper. `--item-id` selects exact ids with `not_listed`; otherwise `--limit` selects the most-listed items. Bid-only listings count toward units/listings but have no price. Market snapshots, leaderboards and PvP cutoffs report Blizzard's `Last-Modified` and its age at read time. Collections and commodity prices are retail-only in practice; Classic auctions omit trade goods.
- Blizzard realm, item and character reads support `--game-version classic-era` and `classic-anniversary`, alongside retail and progression `classic`; doctor reports verification for all four. `character` also takes `REGION REALM NAME`, and `--section` reads PvP summaries/brackets, professions or mount/pet/toy collections as raw `character_section` data.
- `raiderio leaderboard raids --raid` returns guild rankings with region/realm filters, paging and returned/requested counts. `raiderio raids` lists raid/encounter slugs; `affixes` returns this week's affixes; `dungeons` lists season dungeon pools; `cutoffs` returns regional top 0.1%, 1%, 10%, 25% and 40% player-rating cutoffs with UTC `updated_at`.
- Raider.IO profiles add `last_crawled_at`; character profiles include every recent run and each dungeon's best run, with counts and played `spec`, `spec_slug` and `role`. Raid rankings disclose hidden pulls/percentages in `privacy`. Guild roster previews carry rank, active role and realm identity, sort guild master first, and support `--roster-limit` with `roster_truncated`; member counts mean members Raider.IO tracks.
- `icy-veins index-refresh` crawls pages missing from its stale sitemap into a durable local index. It preserves past seasons, resumes a frontier, prioritizes unseen pages, obeys `--max-requests` (default 250) and at least one-second pacing and stops on blocking responses or repeated failures. A bundled index snapshot makes current boss, dungeon and delve pages discoverable before a crawl; doctor reports the index in use. `make icy-veins-snapshot` replaces the bundled snapshot only after a complete crawl.
- Icy Veins discovery combines sitemap, current site menu and site index. Rows report source, sitemap modification time, menu title, indexed headline/publication date and parent; provenance names each source and warns about stale, missing or unreadable data. Searchable content includes raid encounters, dungeons, delves, professions, tier lists, hubs, transmog and PvP subpages.
- Icy Veins converts calculator builds on PvE and PvP guides into `wow_talent_export` references for SimC. Converted rows carry class/spec `build_identity`, `source.converted_from` and tree-data URL. Published equivalent imports add no duplicate on that page; labels merge shared builds. Calculator URLs remain when PvP selections matter or conversion fails, with conversion status and failure reason.
- `wowhead talent-calc` decodes Classic Era/SoD, Classic PTR, TBC, Wrath, Cataclysm and WoW Forever builds into tree points and ranked talents, and MoP Classic builds into tier choices. Unsupported/unreadable builds report `decoded: false` with a reason. Trimmed calculator data is cached for 30 days; glyph, rune and click-order segments remain raw. SimC continues to decode retail builds only.
- Wowhead item sets are searchable/resolvable entities. `entity`/`entity-page` add infobox/map `facts`, quest start/end and ordered chains, and NPC/object locations; `entity` reports spawn counts while `entity-page` keeps coordinates. Listview links retain tab ids and upstream drop/vendor `listview_data`. Linked previews expose `fetch_more_truncated`; Wiki navigation adds `more_available` and `fetch_more_command`.
- Wowhead news and blue-tracker rows include UTC `posted_at` and timestamp-parse counts. Raider.IO run rows include `logged_run_id`, its own logged-run id rather than a Warcraft Logs code. Warcraft Logs guild/character rows add `class_name`; sampled fights add key level/time and difficulty/key-level counts with mixed-cohort notes. Event pages describe next-page retrieval.
- SimC doctor reports ripgrep/binary dependencies, disabled commands and checkout/binary commit mismatch. Priority/opener/describe results report totals and truncation; `run` returns player/target result headers. `sim` reports other actors, ranked profilesets and stat weights; SimC and Raidbots profilesets include `mean_error`, `mean_stddev` and iterations. Simulation disclosures flag default gear and default talents.
- Guide comparisons add subject identities/agreement, bundles without builds and source `content_updated_at`, separate from export time. Icy Veins/Method reads expose requested/served redirects; orchestration persists them on exported and reused rows.
- Successful cached reads include `provenance.cache` with backend, lookups, hits, hit/all-hit flags, hit age/TTL and backend errors. Wrapper totals preserve each provider's own block; ages are unknown whenever any hit came from Redis. Lorrgs, Blizzard and CurseForge gain configurable caches; Blizzard adds the one-hour `BLIZZARD_SNAPSHOT_CACHE_TTL_SECONDS` for collections and market/PvP snapshots, reducing large bodies before caching. Doctors report cache configuration, availability and failures. Blizzard/CurseForge doctor status becomes ready with credentials and degraded without them, with typed capabilities marked as requiring client credentials/API keys; Warcraft Logs status reflects public access, and Lorrgs/Raidbots report ready.

### Changed

- **Envelope and errors:** top-level payload copies are removed. Failures have `kind: "error"`, `data: {}`, parsed `query`, and details under `error.details`; full nested command paths are preserved. Uncaught exceptions become JSON errors on stderr. Exit codes are 2 usage, 3 auth, 4 not found, 5 network/timeout/rate limit/upstream, and 1 other failures. HTTP errors use `auth_failed`, `not_found`, `rate_limited` or `upstream_error`; connection errors use `network_error`. Lorrgs treats inaccessible private reports as `not_found`.
- **Search/resolve fields:** every provider uses `kind: "search_results"`/`"resolve_match"`, `results`/`candidates`, returned-row `count`, complete `total_matches` and `truncated`. Coming-soon/not-supported totals are null. Rows have `provider`, `kind`, `id`, `name`, `url` and `follow_up: {command, surface}`. Migrate `recommended_command`/`recommended_surface` and `alternatives` to `command`/`surface` and `alternative_commands`; article rows drop `entity_type`/`type_name` and repeated metadata slug/title. Raider.IO discovery replaces `profile_url` with `url`; profile/run payloads retain `profile_url`. Lorrgs/WCL resolve replace `resolution` with `resolve_match`; Lorrgs replaces `results` with `candidates` and drops repeated `data.provider`.
- Search stubs use empty lists, `count: 0`, `total_matches: null` and `truncated: false`; resolve stubs include `confidence: "none"`, `resolved`, `match` and `next_command` as applicable. Warcraft Logs report rows carry their site's URL. Lorrgs ranking rows carry Lorrgs URLs; a report URL row preserves that URL, while metadata rows have no URL. Unresolved provider results retain their top `match` and a fallback search when one can help; zero-match results and Warcraft Logs' explicit-only discovery have no fallback.
- **Wrapper discovery:** `--brief` replaces the old subcommand `--compact`; global `--compact` must precede the subcommand. The wrapper keeps provider rows and order, merges by query intent/title fit with a per-provider half-page cap, and exposes `wrapper_ranking` and `merge_policy`, including provider totals and returned merged count. Weak partial/snippet-only matches are not rescaled into full matches. Provider-score ties use provider name, and stale guides remain marked under `--brief`. Bare names do not imply profiles; exact entity titles can still resolve despite intent words. Apostrophes do not break name matches, and namespaced `C_*` API names route to the wiki.
- Wrapper resolve accepts only a provider's high-confidence answer that fits intent. Low-confidence matches cannot block an answer; medium matches can. Unresolved hints and fallback searches retain wrapper ranking order, including low matches; `provider_resolved_candidates` lists high answers blocked by a better-ranked unresolved candidate. `--limit` only sizes ranking diagnostics. Search and resolve run providers concurrently, preserve failures/warnings under `--brief`, and report answered/failed counts. No eligible searching provider is `no_searching_provider`; all failures preserve a shared provider error or report `upstream_error`/`providers_failed`.
- Provider resolve ambiguity is judged over the full candidate set, not the displayed limit. A one-word query resolves high only when it names the match or a declared provider identity; other matches are medium with `confidence_cap.rule: "single_word_query"`. Wrapper hints use `single_word_query_not_named_exactly`. Lorrgs boss composition queries with extra words remain medium with `words_beyond_boss_name`; heroic/normal/LFR boss compositions stay low. Bare boss names, spec rankings and explicit URLs can still resolve. Bare Warcraft Logs report codes are medium; report URLs can resolve high.
- Wrapper calls providers in-process. Doctor reads local state without API probes, keeps provider readiness/tier and exposes `cache_error` with degraded/error status. Removed constant language/invocation metadata is listed below. Passthrough failures use the provider's envelope; expansion mismatches exit 2. Handed-over commands are shell-quoted and never compacted.
- `warcraft guild` is a Raider.IO snapshot under `data.sources.raiderio.summary/provenance`, with every raid's difficulty-specific world/region/realm ranks; 0 means unranked. `active_raid`/`conflicts` are gone. Cross-provider commands preserve source failure codes. Actor-profile accepts report URLs and URL fight scope, uses realm slugs, marks Raider.IO active-spec provenance, and without a fight searches at most ten report fights, kills first.
- Cooldown packets use the fight's difficulty unless overridden. They infer actor/class/spec/boss from the selected fight's Warcraft Logs roster/encounter when Lorrgs is missing, unavailable or lacks players; `--spec-slug` is needed only if the roster lacks a spec, and missing actor selection lists the roster. Deaths are unknown without Lorrgs. Explicit spell ids allow operation during a Lorrgs outage. Source errors, comparison-decline reasons, requested phase and other-source cast counts stay visible.
- Without Lorrgs markers, cooldown phase windows come from Warcraft Logs transitions and carry phase id/name/source. Top parses use their own transitions and count only matching encounter phases; unavailable/missing-phase samples never compare a whole fight to one player phase. `phase_sample_count`, availability reasons and `no_phase_data` disclose this. Use `--actor-id` or `--actor-name` to select the actor and `--spell-id` during a metadata outage. Received externals are excluded only when the actor did not cast them, remain in `received_auras`, and explicit spell ids stay compared. The analyzed fight is excluded from its own top-parse sample.
- Guide orchestration writes under the data root, selects guide candidates only, uses portable relative bundle paths, records provider decline/failure causes and redirects, and rejects scopes with fewer than two providers. Comparisons reject duplicate/fewer-than-two bundles and count a build as shared only across build-capable bundles, with at least two needed.
- Guide-to-SimC handoffs retain exact transport packets/provenance, rotate `--limit` across providers, separate excluded/truncated counts and disclose failed guide pages. Root freshness uses the oldest bundle export; manifest rewrite time is separate. Statuses are `ok`, `partial`, `failed`, `no_build_references`, `all_references_excluded` and `all_handoffs_failed`. Empty/partial requested legs and per-build failures are explicit. Identifying no class/spec fails `build_not_identified`; when every requested leg produces nothing the command fails `simc_handoff_failed`, including `--no-decode` runs.
- Talent packets travel to SimC in memory, without deleted temporary paths or duplicate stdout JSON. `written_packet_path` replaces `packet_written_path`; a real source/kept packet path is cited, otherwise null. Provider results contain `{provider, exit_code, payload}`, and SimC failure queries echo only supplied inputs. Explicit report refs require `--actor-id`; bare report codes use the same identifier rules as Warcraft Logs. Forever refs route to Wowhead. Raw-only log packets require validation before direct SimC input.
- **Guide query migration:** Icy Veins, Method and Wowhead use `kind: "guide_query"` and `data: {bundle, guide, page, query, count, match_counts, matches, top, failed_pages}`. Wowhead replaces `output_dir`/`counts` with `bundle`/`match_counts`, drops `filters` and returns full scored rows rather than preview projections; navigation/gatherer/comment queries remain. Cross-bundle query counts include every kind and build references, and top rows include bundle identity. Method exports return `files` instead of `manifest`. Title/name/label matches rank above mere mentions; blank queries and invalid/missing bundles fail consistently.
- Wowhead search returns five rows by default, resolve limits reach 50, and search supports `--entity-type`. Suggestion ranking preserves upstream order, filters whole words/types/numbers, ranks superseded guides down and never resolves one high. `entity` normalization version moves to `normalized.schema_version`, with old cache records refetched. Inline entity tokens get names, build blocks survive, and guide/share URLs determine expansion. Cached entities report the current call's expansion selection.
- Icy Veins/Method recognize shared class/spec shorthand and punctuation; Icy Veins treats `mythic+`, `m+` and `m plus` alike, Method uses `mythic dungeon`. Method spec-section queries hand off to the section. Icy Veins limits spec guides/intro boosts to actual spec/class/role introductions, classifies article/expansion/old-raid families separately and ranks transmog only for transmog queries. Method class guides require a spec/class slug. Sitemap dates move from Icy Veins `metadata.last_updated` to `metadata.sitemap_lastmod`, Method guide dates are ISO plus original text, and source-specific publication dates break discovery ties.
- **Warcraft Logs:** `report-player-talents` produces raw-only packets without running SimC. Typed damage/aura results omit raw tables unless `--include-raw`; `graphql` returns the API's own data. Typed commands expose all GraphQL partial warnings and never cache partial replies. Finished-report caching starts after two hours without events; live kills still participate in sampled cohorts.
- Warcraft Logs scopes events/player details to fights or explicit windows, accepts report URLs/localized hosts/bare `CODE#fight=N`, honors URL fight scope unless overridden and rejects foreign hosts/site mismatches. Missing fights/scopes and impossible/inverted windows fail clearly. Encounter windows clamp to the fight and echo effective window/clamp fields. Complete guild scope is required; bad enum/finite-value/input-file options are validated before requests. `--difficulty` accepts names; report-list dates accept UTC ISO dates; `--limit` aliases ranking/sample `--top`, and casts expose `--event-limit`.
- Warcraft Logs raid healer rankings default to hps, other raid specs to dps and Mythic+ to score. Report rankings use default metrics and a separate healer pass; `query.metric`, `query.player_metric` and `query.healer_metric` echo the choices. Shared class/spec names/shorthand normalize to provider ids, infer an unambiguous class and reject mismatches; classic/fresh retain their extra specs. `boss-spec-usage` keys include class/spec/role. Aura actors are `aura_holder`/`applied_by` with `row_actor`, and aura comparisons expose left/right/delta total uptime/uses instead of never-filled totals.
- Raider.IO specs/composition keys are class-qualified, regions/realms and class/spec/role filters normalize consistently, and invalid filters fail instead of producing empty samples. Character/guild `realm` is a slug with `realm_name` separate; recent-run `dungeon_slug` is removed in favor of `dungeon`/`short_name` and complete timing/id/url fields; direct search probes match that shape. Sampled commands page as far as limits require, with zero-based `--page` and provider-specific expansion ids documented, with optional `--pages` cap, deduplicate repeated runs and disclose duplicates. Thresholds outside the sampled range have no estimate and explain paging or run-score/player-rating differences.
- Wiki API/event lookup tries canonical titles first and accepts fallback only when every word matches the title; API/event resolution uses returned count plus total/truncation. Events extract arguments, and API lookup includes enums, CVars, widgets, templates, TOC/taint and programming pages. Impossible/special titles and overlong queries fail `invalid_query`; other MediaWiki errors use `api_error` with the upstream code in details.
- SimC identifies talent exports by probing all specs including healers; explicit class/spec and APL/url guesses are checked against the decoded hash, and contradictory guesses are ignored. Class/spec shorthand and case-insensitive names remain supported and are shared with providers. Blizzard hash URLs and retail PTR/Beta refs decode; Classic/Forever refs fail explicitly as non-retail. High decode confidence requires a decoded pair; unresolved probing says how many specs were tested. Relative/bare APL paths resolve predictably, and multi-actor build input selects the first actor with notes.
- SimC exact-build/APL analysis follows rotation dispatch past utility/helper lists and evaluates the decoded hero tree, talent ranks and full operator precedence. Unknown conditions stay unknown. `build.enabled_talents` outputs are token lists with `enabled_talent_count`, and inactive branches identify talent/hero gating. Tokens follow SimC spelling; earlier underscore variants fail `unknown_talent`, so use display names or current decode tokens. Describing a build against another spec's APL fails `invalid_query`.
- SimC `modify-build --add/--remove` accepts spec/hero names, routes edits to the right tree, validates choices/swaps and verifies re-encoding with disclosures; mismatches fail `encode_mismatch`. Transport validation rejects invalid/duplicate ranks and multiple hero trees. `sim` keeps profile run settings unless `--iterations`/`--max-time` explicitly override them, records settings retained/replaced, handles all whitespace-separated options, and reports requested iterations accurately. `compare-apls` uses mean executes across all iterations rather than one sampled sequence; `action_sequence_iterations` is removed. SimC error extras move to `error.details`, executed argv to `data.command`, and previews use the last 20 lines.
- Blizzard reads verified regions with `provenance.verified: true`, supports Classic profiles and resolves display/native-script realms. Credential pairs come wholly from the first complete source, never mixed. CurseForge verifies live reads, returns latest files newest-first while keeping raw upstream order, and includes file display/release type in changelogs. Raidbots rejects malformed refs, supports stdin `--file -` and aligns SimC metrics and multi-actor output.
- HTTP clients use the versioned User-Agent, per-host request pacing and bounded Retry-After. Auth state files/directories use 0600/0700, dotenv discovery stops at the repository root and credential discovery does not mutate the environment. Refresh tokens are neither stored nor used.

## [0.3.0] - 2026-05-08

### Added

- `view-private-reports` scope is now first-class alongside `view-user-profile`. `auth login`, `auth pkce-login`, `auth status`, `auth token`, and `doctor` decode the access token's JWT body to surface `scopes.has_view_private_reports`, and `scope_warning` walks you through what to re-auth for. WCL's token response omits the granted-scope list, so reading the JWT is the only reliable way to know what the user actually has.
- `report-events` now appends a hint when a narrowed slice still resolves to `events.data: null`, pointing at the `--data-type` flag (`casts`, `damage-done`, `healing`, …) rather than surfacing a bare null.

### Changed

- Every WCL command surfaces partial-error context as `notes` and `graphql_warnings` in JSON output via a centralized `_emit(client=client)` path.
- `GuildAttendance` no longer selects `Zone.frozen` — that field was nulling out for real guilds (e.g. `gn / us-malganis`) and tripping the partial-error path. Pagination, rosters, and zone identity continue to flow.

### Fixed

- Private and guild-stealth typed encounter analytics now return populated rows. `v0.2.0` routed authenticated traffic to `/api/v2/user`, but the parsers still expected the legacy `report.table.entries` shape; live WCL responses use `report.table.data.entries` (and `data.auras` for buffs). `report-encounter-damage-source-summary`, `report-encounter-damage-target-summary`, `report-encounter-damage-breakdown`, and `report-encounter-aura-summary` were silently returning zero rows on real reports despite passing the fixtures. The parser now drills into the `data` wrapper.
- WCL `{ "data": ..., "errors": [...] }` partials are tolerated. The client uses a recursive useful-data check: if any leaf value (or non-empty list) is populated at any depth, the response flows through with the error list captured as `last_warnings`. If every leaf is null, the original GraphQL error is raised so users see the real failure rather than a misleading `not_found`.
- `null` GraphQL variables are pruned at the wire. WCL rejects `null` variable values with `Internal server error` instead of treating them as omitted, so `character-rankings ... --spec-name <slug>` and similar flag-driven calls were 500'ing whenever an optional flag was unset alongside a set one. Cache keys use the pruned variable set so cache identity stays stable across `null`/omitted callers.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --scope view-private-reports \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-private-reports` continue to work for public queries; `auth status` reports the missing scope.

## [0.2.0] - 2026-05-06

### Added

- `view-user-profile` scope is now first-class. `auth login`, `auth pkce-login`, `auth token`, `auth status`, and `doctor` expose `scopes.granted`, `scopes.requested`, `scopes.has_view_user_profile`, and a `scope_warning` when the scope is missing. WCL requires this scope to establish a user identity; without it, `userData.currentUser` resolves to null and ACL checks fall through to anonymous.

### Changed

- WCL routes report and guild GraphQL queries through `/api/v2/user` whenever a non-expired user token is saved. Previously every query went to `/api/v2/client` with the client-credentials token, so private and guild-stealth reports returned "permission denied" no matter how many times the user re-authenticated. Cache payloads are namespaced by endpoint family so client- and user-API responses can never collide on disk.
- Public-API probes stay pinned to the client endpoint via a new `force_client=True` opt-out on `rate_limit()` and `probe_live_public_api()`. Without this, broken client credentials could be masked by a working user token.

### Fixed

- `load_provider_auth_state` returns `None` on `OSError` / `JSONDecodeError`, matching the contract `provider_auth_status` already followed. Corrupt or hand-edited state files no longer crash the CLI.
- `auth token` only emits `scope_warning` when there's actually a saved user token; fresh setup, logged-out, and corrupt-state cases now report `scope_warning: null`.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-user-profile` continue to work for public queries; `auth status` reports the missing scope.
