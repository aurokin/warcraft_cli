# Changelog

All notable changes to this repo are recorded here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The workspace ships under a single version — every `pyproject.toml` in the monorepo bumps together.

Add user-visible changes to `[Unreleased]` in the same PR that ships them. See [docs/RELEASE.md](docs/RELEASE.md) for the release flow.

## [Unreleased]

Every binary now speaks one JSON envelope, one error and exit-code vocabulary, and one set of global
output flags, and many commands that used to answer wrong with `ok: true` now answer right or fail.
**Breaking:** payload keys are no longer copied to the top level of the envelope; read them from
`data`.

### Added

- **One envelope on every binary.** `warcraft` and the eleven provider binaries emit exactly `ok`, `provider`, `command`, `kind`, `schema_version` (`"1"`), `query`, `provenance` and `data`, plus `error` on failure (with `data: {}` and `kind: "error"`), and fail with `internal_error` rather than print anything else. `command` is the full subcommand path (`raiderio distribution mythic-plus-runs`), and a failure's `query` echoes the parsed parameters. See [docs/foundation/ERROR_CONTRACT.md](docs/foundation/ERROR_CONTRACT.md); `warcraft schema` prints it as a JSON Schema (`schemas/envelope.schema.json`).
- **Global output flags on every binary** (Wowhead only before): `--compact`, `--compact-max-chars`, `--fields`, `--fields-strict` and `--profile agent|human`, placed before the subcommand; `warcraft <provider> ...` forwards them. `--compact` cuts only prose: URLs, talent and transport strings, export codes, generated SimC profiles and `*command` values stay whole, and every cut path is listed in `provenance.compacted_paths`. A `--fields` path the payload lacks is listed in `fields_missing` instead of printing `{}` (`--fields-strict`: `missing_fields`, exit 2). Failures are always printed whole.
- **No tracebacks.** Anything that escapes a command becomes an error envelope on stderr, and a bad flag, option value or missing argument is `invalid_argument` (exit 2) instead of a usage panel.
- **Provider tiers** in `warcraft doctor` (`wrapper.tiers`, `tier` per row): core `wowhead`, `warcraftlogs`, `simc`; supported `method`, `icy-veins`, `raiderio`, `warcraft-wiki`, `lorrgs` (was experimental); experimental `raidbots`, `blizzard-api`, `curseforge`.
- `raiderio leaderboard raids --raid <slug>`: guild raid rankings for one raid and difficulty, by `--region` and optional `--realm` (slug or display name), with paging and returned-vs-requested counts. `raiderio raids --expansion-id <n>` lists raid and encounter slugs. They replace the WowProgress leaderboards.
- `--help` text on every command, argument and option, and a generated per-command reference in [docs/reference/](docs/reference/README.md).
- Release wheels: pushing a `v*` tag runs the full check suite, then attaches the wheel to the GitHub release (`pipx install <wheel-url>`, `uvx --from <wheel-url> warcraft ...`).
- `wowhead news` and `blue-tracker` rows carry an ISO 8601 UTC `posted_at`; `scan.unparsed_timestamps` counts rows whose time could not be read.
- `simc doctor` reports ripgrep and the SimC binary under `dependencies`, marks the commands a missing one disables, and flags a binary built from a different commit than the checkout.

### Changed

- **Exit codes**: `2` usage (`invalid_query`, `invalid_argument`, `missing_fields`), `3` auth, `4` not found (including upstream 404), `5` network, timeout, rate limit and upstream failures, `1` everything else, on every binary. Provider-specific mappings are listed in ERROR_CONTRACT.md and each provider README.
- **Upstream HTTP failures** are `auth_failed` (401/403), `not_found` (404), `rate_limited` (429) or `upstream_error` (other statuses), timeouts `timeout`, connection failures `network_error`, instead of `http_error`, always with `error.details.status_code` and `url`. Lorrgs answers 401/403 with `not_found` (the report is private).
- HTTP clients send `User-Agent: warcraft-cli/<version>`, space requests to one host by `WARCRAFT_HTTP_MIN_INTERVAL_SECONDS` (default `0.25`) and cap `Retry-After` at 30 s. Auth state files are written 0600 in a 0700 directory, and `.env.local` discovery stops at the git root.
- Handed-over commands (`next_command`, `follow_up.command`, `fallback_search_command`, `fetch_more_command`, cooldown-packet source commands) are shell-quoted. Wowhead, Icy Veins, Method and Warcraft Wiki rows name theirs in `follow_up.command` (was `follow_up.recommended_command`).
- Choosing the Redis cache backend without a URL fails naming the provider's own variables (`METHOD_REDIS_URL`, not `WOWHEAD_*`), and `doctor` prints `redis_url` without credentials.
- `warcraft` calls providers in-process. `doctor` answers offline (no Warcraft Logs auth probe) and drops `language` and `shell_fallback`.
- `warcraft search` and `resolve`: `--brief` is the small payload (was `--compact`, now only the global flag). `search` merges providers by query intent, keeps each provider's own order, caps any provider at half the page, lets the entity provider's exact-name row lead, and reports the rules in `data.merge_policy`. Both report `answered_provider_count`, `failed_provider_count` and `failed_providers[]` (with `exit_code`), and fail when no searching provider answered: with the providers' shared code, `upstream_error` (exit 5) when all failed upstream, otherwise `providers_failed` (exit 1).
- `warcraft resolve` answers with the candidate `search` ranks first, and only when that candidate's own provider resolved it and the query's intent does not rank its family down; otherwise `resolved: false` with `best_unresolved_candidate`, `unresolved_reason` and `fallback_search_command(s)`. `provider` is always `"warcraft"`, the chosen one is `data.selected_provider`, and `--limit` only sizes `--ranking-debug`. Guide queries no longer resolve to Lorrgs or Warcraft Logs spec rows.
- `warcraft guild` is a Raider.IO snapshot: `data.sources.raiderio.summary.raids[]` carries every raid with its own normal/heroic/mythic world, region and realm ranks (`0` means unranked). There is no `active_raid` or `conflicts` block, and a failure keeps Raider.IO's own code.
- `warcraft cooldown-packet`, `actor-profile`, `talent-packet` and `talent-describe` exit with the failing source's code (auth 3, not found 4, network 5) instead of 1.
- `warcraft cooldown-packet` compares at the fight's own difficulty unless `--difficulty` is passed, reports `phase.requested`, and names why no top-parse comparison ran in `comparison.reason` (`no_boss_slug`, `unranked_difficulty`, `lorrgs_spec_ranking_failed`, `disabled_by_sample_limit`). For a report Lorrgs has not cached it returns the Warcraft Logs half with `--actor-id` and `--spec-slug` (`lorrgs.status: "unavailable"`). A fight the report lacks fails `fight_not_found` (exit 4, `error.details.available_fight_ids`); `actor_id_not_found`, `actor_name_not_found` and `lorrgs_fight_not_found` exit 4.
- `warcraft actor-profile` without `--fight-id` works again: it searches at most 10 of the report's fights, kills first (`query.scoped_fight_ids`, `query.fight_scope`), and fails `report_has_no_fights` or `actor_not_found` (exit 4).
- `warcraft guide-compare-query` writes under `<XDG data dir>/warcraft/guide_compare/<query-slug>` by default (was the current directory). A provider that failed is a `provider_failed` or `guide_export_failed` row with `error {code, message}`; when every provider that contributed nothing failed outright, the run fails with their shared code (a network outage: `network_error`, exit 5) instead of `insufficient_guides`, which now lists each provider's decline reason. `--simc-build-handoff` fails `simc_handoff_failed` when every simc leg failed.
- `warcraft guide-builds-simc` reports `summary.simc_handoff_status` (`ok`, `partial`, `failed`, `no_build_references`), excluded builds and per-build failures, and fails `simc_handoff_failed` (exit 1) when every requested leg produced nothing.
- `warcraft guide-compare` rejects fewer than two bundles or the same bundle twice (`invalid_argument`, exit 2); a missing path is `not_found` (exit 4). `talent-describe` reports `written_packet_path` (was `packet_written_path`). Passthrough expansion refusals exit 2 with `provider: "warcraft"`. A malformed `wrapper_ranking.json` is `invalid_config` (exit 2).
- `wowhead` `count` is the rows returned, with `total_matches` and `truncated` beside it. `search`/`resolve` rank every row of Wowhead's suggestion response on Wowhead's own order, match whole query words, drop rows that match none, sort superseded guides down and never resolve one with high confidence; `resolve` prefers a database entity over news and events. A query that is itself a name made of follow-up words ("Soul Link") is searched whole first, and `search <Wowhead entity URL>` answers with that entity.
- `wowhead` guide sections and `guide-query` spell out inline `[spell=N]`/`[item=N]` tokens with the page's names and keep `[build]` blocks. `guide-bundle-refresh` re-exports from the bundle's recorded expansion. `dressing-room` fetches from the share URL's expansion. `entity`'s normalization version moved to `normalized.schema_version`. Entity cache entries from older versions are refetched once.
- `warcraftlogs report-player-talents` no longer runs SimulationCraft: packets are `raw_only`; validate them with `simc validate-talent-transport --build-packet` or use `warcraft talent-packet`. Damage and aura summaries return typed rows only (the raw table is behind `--include-raw`). `graphql` returns the result's own `data`.
- `warcraftlogs` typed commands report GraphQL partial errors from every request in `data.graphql_warnings`, and never cache a partial response. A report counts as finished (24 h cache, sampled cohorts) once its last event is 2 hours old. `?fight=N` report URLs are scoped like `#fight=N`.
- `warcraftlogs report-player-details` and `report-events` require `--fight-id` or a start/end window (`missing_scope`, exit 2); a fight id, encounter or difficulty the report lacks is `not_found` (exit 4, `missing_fight_ids`), and a window starting past the fight's end is `invalid_query` (exit 2), where each used to return an empty slice. Input errors exit 2 and `site_profile_mismatch` exits 3. Credential discovery no longer mutates `os.environ`.
- `warcraftlogs report-encounter-aura-compare` rows carry left/right/delta `reported_total_uptime` and `reported_total_uses`, sorted by the largest uptime change; the always-null `reported_total`/`reported_active_time` fields are gone. `boss-spec-usage` rows are keyed by class + spec + role, and `--spec-name` accepts class + spec (`'Frost Mage'`).
- `simc` identifies a bare talent export by probing every spec (healers included), with case-insensitive class and spec names; a class or spec guessed from an APL file name or talent-calc URL that the hash contradicts is ignored. It reads Wowhead `/talent-calc/blizzard/<hash>` URLs. Failure extras moved into `error.details`, and the executed argv is `data.command`.
- `simc modify-build` takes spec and hero talents by name in `--add`/`--remove`, routing each edit into its own tree, verifies the re-encoded build (`result.verified`, `result.disclosures`), and fails `encode_mismatch` when an edit did not land or something else changed. `--add` on a taken choice node is `invalid_argument` naming the `--remove` that swaps it. Missing or malformed edits are `invalid_argument` (exit 2).
- Talent transport validation compares tiered nodes by rank and rejects a rank above the maximum, a negative rank or a repeated entry; rows from two hero trees leave the packet `multiple_hero_trees`.
- `raiderio` `spec` metrics, `composition` keys and player `spec_slugs` are class-qualified (`priest-holy`); `--contains-spec` accepts both forms. `resolve` judges confidence over every candidate regardless of `--limit`. `guild`/`character` lead words are type hints only; multi-word and punctuated realms resolve. `raids` and `mythic-plus-runs` report `freshness`.
- `warcraft-wiki` fetches `API:`/`Event:` pages by canonical title first and accepts a search fallback only when every query word matches its title (a miss is `not_found`, exit 4). `resolve` is confident only when the top title covers the whole query, and a leading family word stays when a page is titled with the whole query (`class hall`). `event` pages fill `reference.arguments`.
- `lorrgs resolve` refuses to guess between same-named entities (`confidence: "none"`, every tied candidate). `lorrgs zones` returns `data.zones`. `user-report-fights` without a fight exits 2 (`missing_fight`).
- `icy-veins search`/`resolve` keep a guide only when it contains the whole query or every query word (or a word names its family), read `+` as `plus`, send a spec query to that spec's `...-pve-<role>-guide` (a hunter spec never to its pets page), and rank a page updated more than a year before the newest one down (`penalty_stale_page`), so a past season's guide sorts below the current one. `method` searches `mythic+`/`m+` as `mythic dungeon`.
- `icy-veins` and `method` `guide-query` answer bad bundles the same way: missing `not_found` (4), a file `invalid_argument` (2), unreadable `invalid_bundle` (1); a section whose title matches the query ranks above sections that only mention it. A blank `search`/`resolve` query is `invalid_query` (exit 2).
- `blizzard` `realm` and `character` accept display names and either slug spelling (`Mal'Ganis`, `Tarren Mill`); flag-validation failures exit 2. `blizzard` (us/eu/kr/tw) and `curseforge` payloads report `provenance.verified: true`. `curseforge` `data.changelog` names the file's `display_name` and `release_type`.
- `raidbots` rejects an unparseable report reference with `invalid_report_ref` (exit 2); quick-sim reports with several actors carry `actor_count` and `other_actors`.

### Fixed

- `warcraft talent-packet`, `talent-describe` and `simc validate-talent-transport` reach `validated` for hero-tree builds instead of stopping at `simc_trait_resolution_incomplete`.
- `warcraft guild` no longer paired an expired raid with another raid's ranks or labelled every failure `guild_not_found`. `guide-compare-query` no longer leaves an empty `manifest.json` behind, and `resolve "fury warrior guide"` selects the current Wowhead guide again.
- `wowhead news --date-from/--date-to` returned nothing for every window, and `blue-tracker` misread its timestamps as UTC; both now fail `parse_error` when no row's time is readable. Zone, achievement and currency suggestions route to the right entity type. `profiler` fetched the wrong page and answered `ok: true` for a missing list. Host checks no longer accept `evilwowhead.com`. Linked entities are no longer truncated silently.
- `warcraftlogs` sampled analytics counted one pull twice when two guild members uploaded it (now collapsed, counted in `sample.duplicates_removed`), counted `begincast`/`empower*` events as casts (also in `cooldown-packet`), and returned `count: 0` for a mistyped zone or boss (now `not_found`). Truncated event pages and cache use are disclosed. Report codes without digits are accepted; 16-letter slugs and CamelCase names are not read as codes. Missing reports exit 4, denied ones 3; `auth whoami` is never served from cache; NPC and pet targets are named; trash fights are sliced by fight id alone; a non-JSON body is `invalid_response`.
- `simc decode-build` and friends answered `ok: true` for a hash SimC rejected or a binary that crashed part-way, kept talents from the inactive hero tree, and dropped tiered nodes; `modify-build` failed to encode (`No active players in sim!`, healer builds). `apl-branch-compare` compared the left build with itself when given `--right-profile-path`. `find-action` found nothing for queries with regex metacharacters; a missing ripgrep or checkout is now reported as such; `resolve` suggests a runnable command; no temp directories are left behind.
- `raiderio` `resolved_season` was always null, freshness overstated cached data, missing guilds, characters and realms were `invalid_query` (now `not_found`), runs missing a score or level passed score/level filters, a non-JSON body was `internal_error`, and character search rows lacked `profile_url`.
- `raidbots input` / `inspect-report` with a bad id returned the web app's HTML as SimC input; they fail `not_found` (exit 4).
- `icy-veins` parses the rebuilt guide layout and class hubs again. `icy-veins` and `method` guides split into real sections, extract talent export strings into `build_references`, report unfetchable pages in `failed_pages`, and fail `parse_failed` when a page layout no longer matches.
- `warcraft-wiki` `search` covers the `API:` and `Event:` namespaces, keeps highlighted sub-words intact and ranks the named article first; blank queries fail locally; `maxlag`/`readonly` are `upstream_error` and `ratelimited` is `rate_limited`.
- `curseforge addon` reports 401/403 as `auth_failed` (pointing at the numeric-id form) and 404 as `addon_not_found`. `lorrgs comp-ranking` and `spec-ranking` add a note when Lorrgs returns no reports.

### Removed

- **WowProgress** (`wowprogress` binary, passthrough, docs, `WOWPROGRESS_*` variables): every route sits behind a Cloudflare challenge. `warcraft guild-history` goes with it (no other tier-history source), and the root wheel no longer depends on `curl_cffi`.
- `warcraft guild-ranks`: `warcraft guild` carries the same Raider.IO ranks under `data.sources.raiderio.summary.raids`.
- `warcraft guide-compare-query --limit`.
- Top-level payload copies (`results`, `count`, `entity`, `match`, ...) on every binary, and the wrapper's historical top-level keys.
- `--profile debug` (it never emitted its diagnostics) and `WARCRAFTLOGS_METADATA_CACHE_TTL_SECONDS`.
- Development: `make test-live`, `make test-live-matrix` and the per-provider live suites (replaced by the local `make test-e2e` journeys and a weekly keyless run), `make fmt-check`, and the `setup_worktree_env.sh` override variables. Internal Python APIs moved or went away (`warcraft_core.provider_contract` is `warcraft_cli.provider_contract`; `warcraft_core` no longer re-exports submodules or offers `load_env_file`).

## [0.5.0] - 2026-06-25

### Added

- Warcraft Logs site profiles (AUR-497): `warcraftlogs --site retail|classic|fresh ...` now routes OAuth authorize/token endpoints and public/user GraphQL endpoints through the selected Warcraft Logs host (`www`, `classic`, or `fresh`). The wrapper now treats `warcraftlogs` as `expansion_mode=profiled`: `warcraft --expansion retail warcraftlogs ...` selects `--site retail`, classic-family keys (`classic`, `tbc`, `wotlk`, `cata`, `mop-classic`) select `--site classic`, and the new wrapper expansion key `fresh` selects `--site fresh`. `ptr`, `beta`, and `classic-ptr` remain unsupported for Warcraft Logs and are rejected instead of coerced. Live coverage verifies token exchange and GraphQL schema access for all three site profiles when `WARCRAFTLOGS_LIVE_TESTS=1` and credentials are configured.

### Fixed

- Warcraft Logs no longer depends on `simc-cli` at runtime for talent-tree transport validation. The shared `validate_talent_tree_transport` helper now lives in `warcraft_core`, with `simc_cli.talent_transport` kept as a compatibility re-export, and the provider-to-provider import-linter exception was removed (AUR-501).

## [0.4.0] - 2026-06-23

### Added

- Lorrgs provider: new no-auth `lorrgs` command for the public Lorrgs API (`https://api2.lorrgs.io/api/*`) after a user requested support for `lorrgs.io`. Ships `doctor`; static metadata commands (`roles`, `classes`, `specs`, `spec`, `spec-spells`, `zones`, `zone`, `zone-bosses`, `bosses`, `boss`, `boss-spells`, `spell`, `trinkets`); season metadata commands (`current-season`, `season <slug>`); ranking commands `spec-ranking <spec-slug> <boss-slug>` and `spec-ranking-info <spec-slug> <boss-slug>` for top-parse cooldown timelines; `comp-ranking <boss-slug>` with repeatable `--role`/`--spec` filters and kill-time bounds; `search` / `resolve` for Lorrgs ranking URLs, Warcraft Logs report URLs, bare mixed-alphanumeric report codes, and free text spec/boss queries; `report-overview <report-id-or-url>` for report metadata without queueing fight/player timeline work; and cached-only `user-report` / `user-report-fights` reads. Browser-driving the public Lorrgs page showed the UI preserves `type=damage-done` on `/user_reports/<id>/fights`, so `user-report-fights` now preserves `type` from report URLs and accepts `--type`. Each command emits `{ok, provider, command, kind, query, provenance, data}` on success, with provenance carrying the exact `source_url`, API host, site URL, and upstream source posture (`warcraftlogs`, Wowhead tooltips), and `{ok:false, ..., error:{code, message}}` with a nonzero exit (never a traceback) for `not_found`, `invalid_query`, `rate_limited`, `http_error`, `network_error`, and `invalid_response`. Routed through the wrapper as `warcraft lorrgs ...` with `search`/`resolve` ready, `expansion_mode=fixed`, and `supported_expansions=["retail"]`. The CLI intentionally does not expose Lorrgs queued load/dirty endpoints. Live public API coverage is gated by `LORRGS_LIVE_TESTS=1 pytest -q -m live tests/test_lorrgs_live.py`, including the user-provided Warcraft Logs URL `https://www.warcraftlogs.com/reports/bG3xDYPqKjLm8XaR?fight=22&type=damage-done`. See `docs/lorrgs/README.md`.
- Wrapper cooldown evidence packet: new `warcraft cooldown-packet <warcraftlogs-report-url-or-code> --actor-id <source-id> --phase <n>` composes cached Lorrgs report fight data (phase markers, boss casts, boss/spec slugs, player source ids), Lorrgs spell metadata and optional top-parse `spec-ranking` samples, and Warcraft Logs `report-events --data-type casts` for exact player cast timestamps. The packet emits selected phase windows, player cooldown casts in the phase, boss casts, tracked spell metadata, top-parse comparison samples, source commands/provenance, and caveats. It is intentionally evidence-only, not a synthesized cooldown recommendation.
- CurseForge provider scaffold (AUR-499): new `curseforge` command for the public CurseForge addon API, decided GO in AUR-395. First slice ships `curseforge doctor` (install state, `api_key` auth posture for `CURSEFORGE_API_KEY` discovered via `.env.local` → `~/.config/warcraft/providers/curseforge.env` → environment, and capability metadata — `doctor`/`addon` ready, `search`/`resolve` `coming_soon`) and `curseforge addon <slug-or-id>` — resolves the addon (numeric → mod id, else a `gameId=1` slug search) and returns `data.metadata` (raw CurseForge mod record), `data.latest_files` (the mod's `latestFiles`), and `data.changelog` (the newest file's changelog, best-effort: top-level `null` only when the addon has no files; otherwise an object with the file's `body` — `null` when that file exposes no notes — plus `source_url`, or a `{file_id, error}` marker on a failed fetch, never failing the lookup). Each command emits `{ok, provider, command, kind, query, provenance, data}` on success — provenance carries `game_id`/`mod_id`/`slug`/`resolved_by`/`source_urls` — and `{ok:false, ..., error:{code, message}}` with a nonzero exit (never a traceback) for `missing_api_key`, `addon_not_found`, `http_error`, `network_error`, and `invalid_response`. Routed through the wrapper as `warcraft curseforge …` with `expansion_mode=none` (addon game-version compatibility lives inside file records, not the wrapper's expansion axis). **The host, endpoints, and response shapes follow the documented public CurseForge Core API but are pending one-time live confirmation** — every command payload carries `provenance.verified: false`; run `CURSEFORGE_LIVE_TESTS=1 pytest -q -m live tests/test_curseforge_live.py` with a real `CURSEFORGE_API_KEY` to confirm them. See `docs/curseforge/README.md`. Deferred: dependency graph / game-version compatibility / file-download workflows. `search`/`resolve` are not implemented yet but exist as structured `coming_soon` stubs (a JSON envelope with `coming_soon: true` and a `suggested_command`, not a Click "No such command" error), matching the surface `doctor` advertises.
- Additive identity normalization across provider surfaces (AUR-458): raw fields preserved; each surface gains a sibling identity block from the shared `warcraft_core.identity` contract. **raiderio** — `class_spec_identity` on ranking roster rows, resolve character-profile candidates, character search results (class-only `normalized`), and guild `roster_preview` rows (`high` confidence only when both class+spec resolve, else `none`). **raidbots** — `class_spec_identity` on `inspect-report` actor summaries from the sim report's `class`/`specialization` (`high` when both present, `unknown` when both missing). **wowprogress** — `class_spec_identity` on the `character` payload (status `normalized`, `confidence: none`; spec sourced from the SimDPS table when present), and `encounter_identity` on guild encounter kill rows (name-only → `normalized`, `encounter_id: null`). **method** + **icy-veins** — `ability_identity` on Wowhead `spell` linked-entity rows (status `canonical`, `spell_id` set); other entity types unchanged. `docs/foundation/IDENTITY_CONTRACT.md` coverage matrix + notes updated.
- Blizzard API Game Data + Profile reads + live OAuth (AUR-455): completes the AUR-390 scaffold with a client-credentials OAuth token flow (ported from `warcraftlogs`: token fetched once and cached in shared state under `blizzard-api-client-credentials`, keyed by `sha256(region, id, secret)`, reused until ~60s before expiry) and three typed read commands — `blizzard realm <slug>` (dynamic), `blizzard item <id>` (static), and `blizzard character <realm> <name>` (profile, retail only). Region/namespace routing is honored: `--region` (default `BLIZZARD_REGION`, else `us`; `us`/`eu`/`kr`/`tw`/`cn` with aliases like `na`), and `--game-version retail|classic` (or the `--classic` shorthand; passing `--classic` alongside a contradictory explicit `--game-version` is rejected with `unsupported_game_version` rather than silently routing to classic) selects the namespace-class infix; `--locale` passes through. Each command emits `{ok, provider, command, kind, query, provenance, data}` on success — provenance carries `region`/`namespace`/`namespace_class`/`game_version`/`source_url` — and `{ok:false, ..., error:{code, message}}` with a nonzero exit (never a traceback) for `missing_client_credentials`, `unsupported_region`, `unsupported_game_version`, `classic_profile_unsupported`, `http_error`, `network_error`, and `invalid_response`. `blizzard doctor` flips `game_data`/`profile` to `ready` and surfaces the region/routing block. `search`/`resolve` remain `coming_soon` but exist as structured stubs (a JSON envelope with `coming_soon: true` and a `suggested_command`, not a Click "No such command" error), matching the surface `doctor` advertises. **The endpoint hosts, OAuth token URL, and namespace strings follow documented Blizzard API conventions but are pending one-time live confirmation** — `doctor` carries this marker under `region.verification` and every command payload carries `provenance.verified: false`; run `BLIZZARD_LIVE_TESTS=1 pytest -q -m live tests/test_blizzard_api_live.py` with real credentials to confirm them (CN endpoints and classic namespace strings are least certain). ## [0.3.0] - 2026-05-08

### Added

- `view-private-reports` scope is now first-class alongside `view-user-profile`. `auth login`, `auth pkce-login`, `auth status`, `auth token`, and `doctor` decode the access token's JWT body to surface `scopes.has_view_private_reports`, and `scope_warning` walks you through what to re-auth for. WCL's token response omits the granted-scope list, so reading the JWT is the only reliable way to know what the user actually has.
- `report-events` now appends a hint when a narrowed slice still resolves to `events.data: null`, pointing at the `--data-type` flag (`casts`, `damage-done`, `healing`, …) rather than surfacing a bare null.

### Changed

- Every WCL command surfaces partial-error context as `notes` and `graphql_warnings` in JSON output via a centralized `_emit(client=client)` path.
- `GuildAttendance` no longer selects `Zone.frozen` — that field was nulling out for real guilds (e.g. `gn / us-malganis`) and tripping the partial-error path. Pagination, rosters, and zone identity continue to flow.

### Fixed

- Private and guild-stealth typed encounter analytics now return populated rows. `v0.2.0` routed authenticated traffic to `/api/v2/user`, but the parsers still expected the legacy `report.table.entries` shape; live WCL responses use `report.table.data.entries` (and `data.auras` for buffs). `report-encounter-damage-source-summary`, `report-encounter-damage-target-summary`, `report-encounter-damage-breakdown`, and `report-encounter-aura-summary` were silently returning zero rows on real reports despite passing the fixtures. The parser now drills into the `data` wrapper.
- WCL `{ "data": ..., "errors": [...] }` partials are tolerated. The client uses a recursive useful-data check: if any leaf value (or non-empty list) is populated at any depth, the response flows through with the error list captured as `last_warnings`. If every leaf is null, the original GraphQL error is raised so users see the real failure rather than a misleading `not_found`.
- `null` GraphQL variables are pruned at the wire. WCL rejects `null` variable values with `Internal server error` instead of treating them as omitted, so `character-rankings ... --spec-name <slug>` and similar flag-driven calls were 500'ing whenever an optional flag was unset alongside a set one. Cache keys use the pruned variable set so cache identity stays stable across `null`/omitted callers.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --scope view-private-reports \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-private-reports` continue to work for public queries; `auth status` reports the missing scope.

## [0.2.0] - 2026-05-06

### Added

- `view-user-profile` scope is now first-class. `auth login`, `auth pkce-login`, `auth token`, `auth status`, and `doctor` expose `scopes.granted`, `scopes.requested`, `scopes.has_view_user_profile`, and a `scope_warning` when the scope is missing. WCL requires this scope to establish a user identity; without it, `userData.currentUser` resolves to null and ACL checks fall through to anonymous.

### Changed

- WCL routes report and guild GraphQL queries through `/api/v2/user` whenever a non-expired user token is saved. Previously every query went to `/api/v2/client` with the client-credentials token, so private and guild-stealth reports returned "permission denied" no matter how many times the user re-authenticated. Cache payloads are namespaced by endpoint family so client- and user-API responses can never collide on disk.
- Public-API probes stay pinned to the client endpoint via a new `force_client=True` opt-out on `rate_limit()` and `probe_live_public_api()`. Without this, broken client credentials could be masked by a working user token.

### Fixed

- `load_provider_auth_state` returns `None` on `OSError` / `JSONDecodeError`, matching the contract `provider_auth_status` already followed. Corrupt or hand-edited state files no longer crash the CLI.
- `auth token` only emits `scope_warning` when there's actually a saved user token; fresh setup, logged-out, and corrupt-state cases now report `scope_warning: null`.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-user-profile` continue to work for public queries; `auth status` reports the missing scope.
