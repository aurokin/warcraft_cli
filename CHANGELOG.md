# Changelog

All notable changes to this repo are recorded here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The workspace ships under a single version — every `pyproject.toml` in the monorepo bumps together.

Add user-visible changes to `[Unreleased]` in the same PR that ships them. See [docs/RELEASE.md](docs/RELEASE.md) for the release flow.

## [Unreleased]

This release makes every binary behave the same way at the boundary: one JSON envelope that carries
only the envelope keys, one error and exit-code vocabulary, one set of global output flags, and one
in-process provider interface. It also fixes a long list of commands that answered wrong with
`ok: true`. Payload keys are no longer copied to the top level of the envelope: read them from
`data`.

### Added

- **Shared JSON envelope on every binary.** The `warcraft` wrapper and all eleven provider binaries emit exactly `ok`, `provider`, `command`, `kind`, `schema_version` (`"1"`), `query`, `provenance`, and `data`, plus `error` on failure, and nothing else at the top level. On failure `data` is `{}` and `kind` is `"error"`. Defined as TypedDicts in `warcraft_core` and documented in [docs/foundation/ERROR_CONTRACT.md](docs/foundation/ERROR_CONTRACT.md). Every binary refuses to print a malformed envelope (a missing, mistyped, or extra top-level key) and fails with `internal_error` (exit 1) instead.
- `warcraft schema` prints the envelope as a draft 2020-12 JSON Schema, also checked in at `schemas/envelope.schema.json` (`make schema`). It is derived from the TypedDicts and sets `additionalProperties: false` on the envelope and on `error`.
- **Global output flags on every binary.** `--compact`, `--compact-max-chars`, `--fields`, `--fields-strict`, and `--profile agent|human` now work on `warcraft` and all eleven providers (previously Wowhead only); `--pretty` is unchanged. Global flags go before the subcommand, and `warcraft` forwards them on `warcraft <provider> ...` passthrough. A `--fields` path the payload does not have is listed in a `fields_missing` array instead of being dropped (`--fields nope` used to print a bare `{}`); `--fields-strict` still fails with `missing_fields` (exit 2).
- **Process guard.** Each binary runs through `warcraft_core.cli.guarded_run`, so anything that escapes a command becomes an error envelope on stderr instead of a Python traceback, and argument-parsing failures (unknown flag or command, rejected option value, missing argument) are an `invalid_argument` envelope with exit 2 instead of a Rich usage panel.
- **`ProviderSurface` protocol and `PROVIDER` exports.** `warcraft_core.provider` defines pure `search` / `resolve` / `doctor` surfaces returning envelopes; every provider package exports `PROVIDER` from `<pkg>/provider.py`, and the Typer commands are thin wrappers over it.
- **Provider tiers.** `warcraft doctor` reports `wrapper.tiers` and a `tier` on every provider row: core (`wowhead`, `warcraftlogs`, `simc`), supported (`method`, `icy-veins`, `raiderio`, `warcraft-wiki`, `lorrgs`), experimental (`raidbots`, `blizzard-api`, `curseforge`).
- **Raider.IO raid leaderboards.** `raiderio leaderboard raids --raid <slug>` returns guild raid rankings (kind `raid_leaderboard`) for one raid and difficulty, scoped by `--region` (world/us/eu/kr/tw/cn, same aliases as every Raider.IO command) and optional `--realm` (a display name such as `"Tarren Mill"` is slugified), with `--page`/`--limit` paging, returned-vs-requested `sample` counts, freshness, and raider.io citations. `raiderio raids --expansion-id <n>` lists the raid and encounter slug catalog (kind `raid_catalog`). `raiderio doctor` reports both and the new `RAIDERIO_RAID_RANKINGS_CACHE_TTL_SECONDS` TTL (default 900s). These replace the retired WowProgress guild leaderboards.
- **Help text everywhere.** Every command, positional argument, and option on every binary prints a description in `--help`.
- **Generated command reference.** `docs/reference/<binary>.md` is generated from the Typer apps by `make reference`, with a test that fails when it is stale.
- **Local end-to-end suite.** `make test-e2e` runs the journeys under `tests/e2e/` through the installed binaries against the real providers with the keys in `~/.config/warcraft/providers`, with isolated caches and no silent skips (`WARCRAFT_E2E_SKIP` excludes providers explicitly). It never runs in CI except for the keyless journey files, weekly. See `docs/architecture/E2E_TESTING.md`. `make test-canary` runs the Wowhead parser canary, the only live test outside `tests/e2e/`.
- **Distribution.** A release workflow builds the wheel on a `v*` tag and attaches it to the GitHub release, so `pipx install <wheel-url>` and `uvx --from <wheel-url> warcraft ...` work. CI also builds the wheel and proves each provider package installs and runs in isolation.
- `error.details` on upstream HTTP failures across providers, carrying `status_code` and `url`.
- `raidbots search` and `raidbots resolve`: structured `not_supported` stubs (exit 0) so the cross-provider surface exists; Raidbots publishes no report index.
- `warcraft search` and `warcraft resolve` always report `answered_provider_count`, `failed_provider_count` and `failed_providers[]`, including under `--brief`; provider rows carry `ok`, `error` and `answered`. `warcraft search` reports `truncated` when `--limit` cut the merged list. When `warcraft resolve` resolves nothing it returns `fallback_search_command`, `fallback_search_commands[]` and `best_unresolved_candidate`. `excluded_providers` rows carry a `reason`.
- `warcraft cooldown-packet` payloads carry `phase.requested` (the `--phase` asked for) next to `phase.selected`.
- Guide bundles record the pages the provider could not fetch as `failed_pages` in `manifest.json`; `guide-query` results carry the same block and `warcraft guide-compare` reports `failed_page_count` per bundle.
- `wowhead news` and `blue-tracker` rows carry an ISO 8601 UTC `posted_at` next to the upstream `posted`, and `scan.unparsed_timestamps` counts rows whose timestamp could not be read. Every `wowhead resolve` candidate exposes `metadata.updated`.
- `warcraftlogs` sampled analytics report `freshness.cache_hit_count`, `freshness.upstream_request_count` and `freshness.served_entirely_from_cache`. `ability-usage-summary` reports `sample.kills_with_truncated_events_count` and `usage.total_casts_is_lower_bound` when kills overflow `--event-limit`, and `report-encounter-casts` reports `casts.truncated` and a note when its aggregates cover only the first `--limit` events of the fight.
- `simc doctor` reports ripgrep and the SimC binary under `dependencies`, marks the commands that need a missing one `unavailable`, flags a `simc` binary built from a different commit than the checkout, and describes the `sim` command. `invalid_build` errors name the rejecting binary in `error.details.simc_binary`.
- `simc compare-apls` and `variant-report` disclose under `sampling` and `action_sequence_iterations` that `action_counts`, `action_cpm` and `top_action_deltas` come from the single iteration SimulationCraft records an action sequence for; DPS and fight length remain means over all iterations.
- `simc` reads a Wowhead `/talent-calc/blizzard/<hash>` URL (only from wowhead.com and its subdomains) as a plain WoW talent export, so `modify-build`'s own `result.wowhead_url` can be fed back in. A build-input link that is not a decodable build reference fails with `unsupported_build_reference` (exit 2) and `error.details.reference_type`.
- `simc modify-build` payloads carry `result.verified` and `result.disclosures`, and report keystones SimC's encoder grants on its own under `result.diff_from_base.inactive_hero`.
- `raiderio character` and `raiderio guild` report `freshness` (`fetched_at`, `cache_hit`, `cache_ttl_seconds`) in `data` and in `provenance`.
- `lorrgs comp-ranking` adds `data.notes` when Lorrgs returns no composition reports, so an empty upstream ranking is not read as a ranking.
- `warcraft-wiki` classifies pages in the wiki's `Event:` namespace as `event_reference`, and `search` covers that namespace.
- Non-live tests run under a socket/httpx/curl_cffi network guard, so a test that reaches a provider endpoint fails, and provider file caches are disabled for non-live tests.
- **Tooling.** `make install` (uv sync), `make complexity-gate` (`xenon --max-absolute C packages`), `make deadcode` (vulture with `scripts/vulture_allowlist.py`), `make skills`, `make reference`, `make schema`, and `make build`; `make check` runs lint, typecheck, import boundaries, complexity gate, dead code, and `make coverage`, the fast tests with `pytest-cov` over every package that fail below a coverage floor. Pre-commit gains gitleaks, complexity-gate, and deadcode hooks.
- **CI.** Installs with `uv sync` and a cached uv setup; the lint job runs ruff, mypy, import boundaries, the complexity gate, and dead code; the unit-test job runs `make coverage`, so CI fails below the same coverage floor; every workflow declares a least-privilege `permissions` block; gitleaks secret scanning; `.github/dependabot.yml` for weekly pip and github-actions updates. The weekly `live-contracts.yml` runs the Wowhead parser canary and the keyless end-to-end journeys with no secrets and never gates a pull request.

### Changed

- **Exit codes follow one vocabulary** instead of "1 for everything": `2` usage errors (bad flags or arguments, `invalid_query`, `invalid_argument`, `missing_fields`), `3` auth required or rejected, `4` not found (including upstream 404), `5` network, timeout, rate limit, and other upstream failures, `1` everything else. A provider may map its own codes onto the same exits and documents them in its README. This applies to every binary. Notable deltas: `icy-veins guide|guide-full|guide-export` on a 404 page exits 4 `not_found` (was 1 `invalid_guide_ref`); `simc log-actions` pointed at a directory exits 4; `curseforge addon` reports 401/403 as `auth_failed` and 404 as `addon_not_found`; `blizzard` flag-validation failures (`unsupported_region`, `unsupported_game_version`, `classic_profile_unsupported`) exit 2 and list the accepted values as plain text; `warcraftlogs` input failures (`missing_spec`, `missing_scope`, `missing_boss`, `missing_query`, `invalid_variables`, `ambiguous_boss`, `boss_scope_mismatch`, the OAuth callback mismatches) exit 2 and `site_profile_mismatch` exits 3; `lorrgs` answers HTTP 401/403 with `not_found` (exit 4), because Lorrgs takes no credentials and a refusal means the report is private.
- Upstream HTTP failures carry precise codes instead of one generic `http_error`: 401/403 `auth_failed`, 404 `not_found`, timeouts `timeout`, connection failures `network_error`, 429 `rate_limited`, other 5xx `upstream_error`.
- **`command` is the full subcommand path** in every envelope (`raiderio distribution mythic-plus-runs`, `warcraftlogs auth status`), on success and on failure alike, whether the failure came from a usage error, a handled failure, or an unexpected exception. The value of a global flag is never the label.
- **A failure's `query` echoes the command's parsed parameters** (OAuth authorization codes and global output flags excepted) instead of `null`, so a rejected request is machine-readable. The exceptions are listed in `docs/foundation/ERROR_CONTRACT.md`.
- **The `warcraft` wrapper calls providers in-process** through their `PROVIDER` surfaces, and its passthrough commands are generated from the provider registry. `warcraft doctor` answers offline: it no longer performs a live Warcraft Logs auth probe and reports `installed: true` for every registered provider.
- `warcraft` envelopes follow the contract: payloads live under `data`, failure context under `error.details`, every failure has `kind: "error"`, and provider payloads embedded in `search`/`resolve`/`doctor` output are the provider's envelope verbatim (`providers[].payload.data.*`). `warcraft resolve` always reports `provider: "warcraft"`; the chosen provider is `data.selected_provider` (null when nothing resolved).
- `warcraft search` and `warcraft resolve` take `--brief` (was `--compact`) for the smaller wrapper payload; `--compact` is the global output flag only, and passing it after the subcommand is a usage error. `--limit` caps the merged output as well as each provider request.
- `warcraft search` merges providers by query intent: each provider's own order is kept (`merge_policy.rule: interleave_provider_order_then_per_provider_cap`), no provider may take more than half the page, a bare entity name is not answered with player profiles (Raider.IO rows are marked `wrapper_ranking.off_intent` and only fill what on-intent rows leave), the entity provider's top row anchors the page when its title is or starts with the query (`warcraft search thunderfury` leads with item 19019), one slot is reserved for a character or guild named exactly the query, and a guide the provider flagged as superseded carries `wrapper_ranking.stale_guide`. Scores are normalized per provider with a floor before merging. `data.merge_policy` reports the caps and the rows they deferred or withheld. Queries starting with `world` and region-prefixed free text longer than `<region> <realm> <name>` are no longer read as profile lookups, while multi-word realms (`eu tarren mill Cotti`) still are.
- `warcraft guild` is a single-source Raider.IO snapshot: `sources` carries only `raiderio`, the `conflicts` block is gone, and a failing source re-emits Raider.IO's own error code and exits with its own code. There is no `active_raid`: `sources.raiderio.summary.raids[]` carries every raid, each joined to its own ranks by `raid_slug`, because Raider.IO carries no raid start/end window.
- `warcraft guild-ranks` sources from Raider.IO: `source: "raiderio"`, `raids[]` rows with `raid_slug`, `summary`, per-difficulty boss kills and `ranks.normal|heroic|mythic` world/region/realm ranks (Raider.IO reports `0` for unranked), and `data.provider_payload` is the full Raider.IO envelope. Wrapper ranking boosts `raiderio` for guild-profile intents.
- Wrapper composites (`cooldown-packet`, `actor-profile`, `talent-packet`, `talent-describe`) exit with the failing source's own code (auth 3, not found 4, network 5) instead of 1. `warcraft guide-compare` with fewer than two bundles and `guide-compare-query` with an unsupported `--provider` are `invalid_argument` (exit 2); a missing bundle path is `not_found` (exit 4) and a file `invalid_argument` (exit 2). A malformed `~/.config/warcraft/wrapper_ranking.json` fails with `invalid_config` (exit 2).
- `warcraft cooldown-packet` compares at the Warcraft Logs fight's own difficulty unless `--difficulty` is passed (it used to assume mythic), and skips the comparison with a note for a difficulty Lorrgs does not rank. For a report Lorrgs cannot serve it degrades instead of failing: with `--actor-id` and `--spec-slug` it returns the Warcraft Logs cast timeline with `lorrgs.status: "unavailable"` (the reason names the real failure; only a `not_found` is reported as uncached) and `player.class_slug` from `--spec-slug`; without them it fails naming the flags.
- `warcraft actor-profile` without `--fight-id` reads the report's fight list and scopes the roster lookup to a bounded set of fights (kills first, at most 10), reported in `query.scoped_fight_ids` and `query.fight_scope`. A report with no fights fails `report_has_no_fights` (exit 4); a name missing from the fights read fails `actor_not_found` (exit 4) with `error.details.fight_scope`.
- `warcraft guide-builds-simc` hands each build reference to simc in the form its type requires and reports `summary.simc_handoff_status` as `ok`, `partial` (a leg worked for some builds), `failed` (a requested leg produced nothing, named in `summary.empty_requested_legs`), or `no_build_references`, plus `summary.partial_requested_legs`, `summary.failed_page_count`, `bundle_health`, `excluded_builds` with a reason each, and per-build `failures` carrying simc's error code. When every requested leg produced nothing it fails with `simc_handoff_failed` (exit 1) and the packet under `error.details`.
- `warcraft guide-compare-query` without `--out-root` writes under `<XDG data dir>/warcraft/guide_compare/<query-slug>` instead of the current directory, and its `insufficient_guides` failure carries the per-provider decline reasons under `error.details`.
- `warcraft talent-describe` reports the file it wrote as `written_packet_path` (was `packet_written_path`), matching `talent-packet`.
- `warcraft <provider>` passthrough with a provider that has no expansion axis reports the advisory at `data.expansion_advisory` (or `error.details.expansion_advisory`); `unsupported_provider_expansion` and `duplicate_expansion_argument` refusals report `provider: "warcraft"`, name the target in `error.details.provider`, and echo `{provider, expansion}` as `query`.
- All HTTP clients send `User-Agent: warcraft-cli/<version> (+https://github.com/aurokin/warcraft_cli)`, and requests pass through a per-host minimum interval (`WARCRAFT_HTTP_MIN_INTERVAL_SECONDS`, default `0.25`, `0` disables). A server `Retry-After` is capped at 30 seconds.
- Provider auth state files (`~/.local/state/warcraft/providers/<provider>.json`) are written 0600 inside a 0700 directory, and an existing file is re-tightened on save.
- `.env.local` discovery stops at the enclosing git repository root instead of walking every ancestor up to `/`.
- `warcraftlogs` credential discovery no longer mutates `os.environ`: the first layer (`.env.local`, `~/.config/warcraft/providers/warcraftlogs.env`, the process environment) holding a complete ID/secret pair wins, and `auth status`/`doctor` report `credential_source: null` when no layer is complete.
- `warcraftlogs report-player-talents` no longer runs SimulationCraft itself. Standalone packets are `raw_only` with `validation.reason: simc_backend_unavailable`; upgrade them with `simc validate-talent-transport --build-packet <packet>`, or use the `warcraft` wrapper, which does it for you.
- `warcraftlogs` damage and aura summaries return typed rows only; the untyped Warcraft Logs table entry is behind `--include-raw` (one fight's damage-source-summary dropped from about 561 KB to 43 KB).
- `warcraftlogs graphql` returns the GraphQL result's own `data` object, even when the API reports partial errors (those move to `provenance.graphql_warnings`); `--introspect` returns `data.__schema`.
- `warcraftlogs report-player-details` and `report-events` require the slice shapes Warcraft Logs answers (`--fight-id`, or both `--start-time` and `--end-time`) and fail with `missing_scope` (exit 2) otherwise; `report-events`, `report-table`, `report-graph`, `report-rankings` and `report-player-details` fail with `not_found` (exit 4) when a `--fight-id`, `--encounter-id` or `--difficulty` names a fight the report does not have, with `error.details.missing_fight_ids`. Each used to return an empty slice with `ok: true`.
- `wowhead` `count` is the number of rows returned on `search`, `resolve`, `news`, `blue-tracker`, `guides` and `guide-bundle-search`; the pre-limit total is `total_matches`, next to `truncated`.
- `wowhead`, `icy-veins`, `method` and `warcraft-wiki` search/resolve rows name their next command in `follow_up.command` (was `follow_up.recommended_command`), like `lorrgs`.
- `wowhead search` and `resolve` rank every row of Wowhead's suggestion response (the `results` dropdown and every `categories` list, one row per entity, reported in `suggestion_merge` and each row's `metadata.suggestion_lists`) on Wowhead's own database and guide order (`upstream_database_rank`), so the entity a query names leads (`wowhead resolve "argent dawn"` answers Faction 529; `--expansion wotlk search thunderfury` leads with Thunderfury). The guide order counts only when the query says `guide` or `guides`, or `resolve --entity-type guide` is set. Query words match whole words, ignoring `the`, `of`, `a`, `an`, `and`, `in`, `on`, `for`, `to`. A row whose text holds none of the query words is dropped and counted in `suggestion_merge.unmatched_rows_dropped`; a row holding some of them stays, marked `some_terms_match`, and scores less. A guide flagged `stale_guide` sorts below every current row that matches the query at least as closely, and `resolve` never answers one with high confidence.
- `wowhead resolve` answers with a database entity: news posts and world events rank behind every entity and become the `match` only when the response holds no entity or the article outscores the best entity by more than an exact name match is worth. `resolve` drops to medium confidence with no `next_command` when its best guide is far older than the other guides in the response.
- `wowhead resolve --entity-type mount|recipe|battle-pet` is a usage error (exit 2); Wowhead's suggestion endpoint does not label those types, so they used to return nothing.
- `wowhead entity` and `entity-page` put the normalization version at `normalized.schema_version` (`wowhead.entity.v1` / `wowhead.entity_page.v1`); the top-level `schema_version` is the envelope's `"1"`. `wowhead --stream` writes a JSON Lines header that is the envelope with the streamed collection emptied and `data.stream` naming it.
- `simc` build commands identify a bare talent export by probing every spec SimulationCraft knows, healers included; `invalid_query` says whether no spec or several decode the build, and names what was probed when `--actor-class` narrowed it. Class and spec are case-insensitive (`Death Knight` and `death_knight` mean `deathknight`), and a class/spec SimC has no spec for (or a pair such as `mage holy`) is `invalid_query` (exit 2) listing the valid values. When identification cannot run because the SimC binary or its generated data is missing, the error is `identify_failed` (exit 1) naming what is missing.
- `simc` build input: an empty build-input option (`--talents ""`) is a usage error naming it, `decode-build`/`identify-build` with no build are `invalid_query` (exit 2), `--enable`/`--disable` accept a talent's display name and fail `unknown_talent` (exit 2) for a name that is not a talent of the class, and the class and spec an `--apl-path` file name suggests only fill what the caller left out; a guess that names no SimC spec is dropped with an `ignored apl name` source note. An `--apl-path` that does not exist fails `not_found` (exit 4).
- `simc modify-build`: `--add`/`--remove` work for spec and hero talents by name and route each edit into its own tree; a talent the spec cannot take is `unknown_talent` (exit 2), and a hero talent counts when the spec can select its hero tree; a malformed `--add` is `invalid_argument` (exit 2, was `invalid_add`); no `--swap-*-tree-from`, `--add` or `--remove` is `invalid_argument` (exit 2, was `no_modifications` exit 1). `compare-builds` rejects an unknown `--tree` with `invalid_argument` and fails when no `--other` decodes, with succeeded/failed counts in `data.summary`.
- `simc` failure extras moved from the top level of the error object into `error.details` (`build_spec`, `identity`, and `generated_profile` on `decode-build`; `command`, `stdout_preview`, and `stderr_preview` on `sync`, `build`, `sim`, and `run`); the executed SimC/git argv is `data.command` on success. Preview lines are clipped to 200 characters.
- Talent transport validation compares tiered-node entries by rank like any other entry, rejects a row whose rank exceeds the entry's max rank (`rank_exceeds_max_rank`) or that repeats an entry (`duplicate_entry`), and lists the keystones SimC grants for unselected hero trees under `validation.round_trip.ignored_unselected_hero_entries`.
- `raiderio raids` and `raiderio mythic-plus-runs` report `freshness.fetched_at` (when the response came off the wire, stored with the cached body) and `freshness.cache_hit`; sampled commands keep `sampled_at` and report the oldest page's `fetched_at`. Distribution and threshold `--metric` help lists every accepted metric.
- `raiderio search`/`resolve` read `guild`/`character` as a type hint only when it leads the query, so `raiderio search "Liquid Guild"` finds that guild. An explicit `--kind` overrides the hint and filters every candidate; an unsupported `--kind` is `invalid_argument` (exit 2). Realms of up to three words (`us area 52 Roguecane`) and punctuated realms (`mal'ganis`, `mal-ganis`, `malganis`) resolve through the direct profile path.
- `lorrgs resolve` no longer guesses between entities that share a name (`frost chimaerus`, `frost mage salhadaar`): it returns `resolved: false`, `confidence: "none"` and every tied candidate, judged over every candidate regardless of `--limit`, with `count` and `truncated`. A report reference resolves at `medium` confidence with a caveat that Lorrgs refuses reports Warcraft Logs keeps private.
- `lorrgs` moved from the experimental tier to supported.
- `lorrgs zones` emits `data: {"zones": [...]}` instead of a bare array in `data`.
- `icy-veins guide-query` and `method guide-query` answer the same mistakes the same way: a missing bundle path is `not_found` (exit 4), a file is `invalid_argument` (exit 2), a directory that is not a readable bundle (no manifest, a corrupt JSONL row or manifest, a missing listed file, a mistyped nested field) is `invalid_bundle` (exit 1), and an unsupported `--kind` is `invalid_argument` (exit 2). `warcraft-wiki article-query` follows the same rules. `icy-veins guide-query --kind` accepts comma-separated values.
- Icy Veins article heading titles are returned as the page renders them; the rendered `1.`/`2.3.` numbering is stripped from the contents list, `article.text` and section text.
- `warcraft-wiki api`/`api-full`/`event`/`event-full` fetch the canonical namespaced title first (`API:CreateFrame`, `Event:PLAYER_LOGIN`), then the pre-namespace or handler title, then the bare title, and only then fall back to ranked search, which accepts a page only when every query word matches a whole word or camel-case component of its title. A miss is `not_found` (exit 4) with the rejected candidates in `error.details.candidates`, replacing `invalid_api_ref`/`invalid_event_ref` (exit 1).
- `warcraft-wiki search` scores MediaWiki's rank at no more than 10 points, always shown as `upstream_rank_<n>`, and no longer drops zero-scoring rows. `warcraft-wiki resolve` reports `resolved: true` only when the top candidate's match reasons cover the whole query; upstream rank, family and intent bonuses (and `query_contains_title`) no longer make a candidate confident on their own.
- `blizzard` and `curseforge` are verified live: `blizzard` payloads carry `provenance.verified: true` for us, eu, kr, and tw (`cn` stays unverified, and `doctor` reports `live_confirmed`), and `curseforge` payloads carry `provenance.verified: true`. `--help`, `doctor` and every payload state the same posture. Both stay experimental because their command surface is thin.
- Expansion keys and aliases are shared across binaries via `warcraft_core.expansions`; the Warcraft Logs `--site` mapping is derived from the same table.
- Docs: `README.md` is a short pointer with a tiered provider table; `docs/USAGE.md` keeps workflows and conventions and links the generated reference for flags; `docs/ROADMAP.md` is tiers, next work, and deferred candidates; provider READMEs describe current behavior. Design history lives in git log, not in the docs tree.
- Tooling: mypy covers all 16 packages; ruff enables the bandit rules S102, S103, S105, S106, S107, S108, S324, S501, S603, S607; `make deadcode` runs vulture at confidence 60 (was 80).
- `scripts/dev_deploy.sh` derives the console-script list from the root `[project.scripts]` (it previously omitted `lorrgs`) and prefers `uv sync --all-extras` when `uv` is on PATH; `WARCRAFT_BIN_NAMES` is gone (setting it fails with a pointer to `--bin-name`).
- (internal) Per-package `pyproject.toml` files no longer point `readme` outside the package directory (hatchling rejected it, breaking every isolated provider install); `warcraft-cli` no longer depends on `httpx`; `warcraft_core.provider_contract` moved to `warcraft_cli.provider_contract`; `warcraft_core.talent_transport` takes an injectable `backend`, with `simc_cli.talent_transport.simc_backend()` providing the SimulationCraft executor.

### Fixed

## [0.3.0] - 2026-05-08

### Added

- `view-private-reports` scope is now first-class alongside `view-user-profile`. `auth login`, `auth pkce-login`, `auth status`, `auth token`, and `doctor` decode the access token's JWT body to surface `scopes.has_view_private_reports`, and `scope_warning` walks you through what to re-auth for. WCL's token response omits the granted-scope list, so reading the JWT is the only reliable way to know what the user actually has.
- `report-events` now appends a hint when a narrowed slice still resolves to `events.data: null`, pointing at the `--data-type` flag (`casts`, `damage-done`, `healing`, …) rather than surfacing a bare null.

### Changed

- Every WCL command surfaces partial-error context as `notes` and `graphql_warnings` in JSON output via a centralized `_emit(client=client)` path.
- `GuildAttendance` no longer selects `Zone.frozen` — that field was nulling out for real guilds (e.g. `gn / us-malganis`) and tripping the partial-error path. Pagination, rosters, and zone identity continue to flow.

### Fixed

- Private and guild-stealth typed encounter analytics now return populated rows. `v0.2.0` routed authenticated traffic to `/api/v2/user`, but the parsers still expected the legacy `report.table.entries` shape; live WCL responses use `report.table.data.entries` (and `data.auras` for buffs). `report-encounter-damage-source-summary`, `report-encounter-damage-target-summary`, `report-encounter-damage-breakdown`, and `report-encounter-aura-summary` were silently returning zero rows on real reports despite passing the fixtures. The parser now drills into the `data` wrapper.
- WCL `{ "data": ..., "errors": [...] }` partials are tolerated. The client uses a recursive useful-data check: if any leaf value (or non-empty list) is populated at any depth, the response flows through with the error list captured as `last_warnings`. If every leaf is null, the original GraphQL error is raised so users see the real failure rather than a misleading `not_found`.
- `null` GraphQL variables are pruned at the wire. WCL rejects `null` variable values with `Internal server error` instead of treating them as omitted, so `character-rankings ... --spec-name <slug>` and similar flag-driven calls were 500'ing whenever an optional flag was unset alongside a set one. Cache keys use the pruned variable set so cache identity stays stable across `null`/omitted callers.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --scope view-private-reports \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-private-reports` continue to work for public queries; `auth status` reports the missing scope.

## [0.2.0] - 2026-05-06

### Added

- `view-user-profile` scope is now first-class. `auth login`, `auth pkce-login`, `auth token`, `auth status`, and `doctor` expose `scopes.granted`, `scopes.requested`, `scopes.has_view_user_profile`, and a `scope_warning` when the scope is missing. WCL requires this scope to establish a user identity; without it, `userData.currentUser` resolves to null and ACL checks fall through to anonymous.

### Changed

- WCL routes report and guild GraphQL queries through `/api/v2/user` whenever a non-expired user token is saved. Previously every query went to `/api/v2/client` with the client-credentials token, so private and guild-stealth reports returned "permission denied" no matter how many times the user re-authenticated. Cache payloads are namespaced by endpoint family so client- and user-API responses can never collide on disk.
- Public-API probes stay pinned to the client endpoint via a new `force_client=True` opt-out on `rate_limit()` and `probe_live_public_api()`. Without this, broken client credentials could be masked by a working user token.

### Fixed

- `load_provider_auth_state` returns `None` on `OSError` / `JSONDecodeError`, matching the contract `provider_auth_status` already followed. Corrupt or hand-edited state files no longer crash the CLI.
- `auth token` only emits `scope_warning` when there's actually a saved user token; fresh setup, logged-out, and corrupt-state cases now report `scope_warning: null`.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-user-profile` continue to work for public queries; `auth status` reports the missing scope.
