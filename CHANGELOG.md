# Changelog

All notable changes to this repo are recorded here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The workspace ships under a single version — every `pyproject.toml` in the monorepo bumps together.

Add user-visible changes to `[Unreleased]` in the same PR that ships them. See [docs/RELEASE.md](docs/RELEASE.md) for the release flow.

## [Unreleased]

Every binary now speaks one JSON envelope, one error and exit-code vocabulary, and one set of global
output flags, and many commands that used to answer wrong with `ok: true` now answer right or fail.
**Breaking:** payload keys are no longer copied to the top level of the envelope; read them from
`data`.

### Added

- `icy-veins` and `method` `guide`, `guide-full` and `guide-export` report `data.redirect` (`{requested, served, message}`) when the site serves another guide than the one requested, as Icy Veins does for retired pages; `warcraft guide-compare-query` carries it on each `provider_results` row, exported or reused (it is saved in `manifest.json`).
- **One envelope on every binary.** `warcraft` and the eleven provider binaries emit exactly `ok`, `provider`, `command`, `kind`, `schema_version` (`"1"`), `query`, `provenance` and `data`, plus `error` on failure (with `data: {}` and `kind: "error"`), and fail with `internal_error` rather than print anything else. `command` is the full subcommand path (`raiderio distribution mythic-plus-runs`), and a failure's `query` echoes the parsed parameters. See [docs/foundation/ERROR_CONTRACT.md](docs/foundation/ERROR_CONTRACT.md); `warcraft schema` prints it as a JSON Schema (`schemas/envelope.schema.json`).
- **Global output flags on every binary** (Wowhead only before): `--compact`, `--compact-max-chars`, `--fields`, `--fields-strict` and `--profile agent|human`, placed before the subcommand; `warcraft <provider> ...` forwards them. `--compact` cuts only prose: URLs, talent and transport strings, export codes, generated SimC profiles and `*command`/`*input` values stay whole (so `raidbots input`'s `data.input`, an addon export with `# ...` comments, stays paste-ready), and every cut path is listed in `provenance.compacted_paths`. A `--fields` path the payload lacks is listed in `fields_missing` instead of printing `{}` (`--fields-strict`: `missing_fields`, exit 2). Failures are always printed whole.
- **No tracebacks.** Anything that escapes a command becomes an error envelope on stderr, and a bad flag, option value or missing argument is `invalid_argument` (exit 2) instead of a usage panel.
- **Provider tiers** in `warcraft doctor` (`wrapper.tiers`, `tier` per row): core `wowhead`, `warcraftlogs`, `simc`; supported `method`, `icy-veins`, `raiderio`, `warcraft-wiki`, `lorrgs` (was experimental); experimental `raidbots`, `blizzard-api`, `curseforge`.
- `raiderio leaderboard raids --raid <slug>`: guild raid rankings for one raid and difficulty, by `--region` and optional `--realm` (slug or display name), with paging and returned-vs-requested counts. `raiderio raids --expansion-id <n>` lists raid and encounter slugs. They replace the WowProgress leaderboards.
- `--help` text on every command, argument and option, and a generated per-command reference in [docs/reference/](docs/reference/README.md).
- Release wheels: pushing a `v*` tag runs the full check suite, then attaches the wheel to the GitHub release (`pipx install <wheel-url>`, `uvx --from <wheel-url> warcraft ...`).
- `wowhead news` and `blue-tracker` rows carry an ISO 8601 UTC `posted_at`; `scan.unparsed_timestamps` counts rows whose time could not be read.
- `simc doctor` reports ripgrep and the SimC binary under `dependencies`, marks the commands a missing one disables, and flags a binary built from a different commit than the checkout.
- `warcraft cooldown-packet` reports `cooldowns.player_casts.other_source_cast_count`; casts from any source other than the actor are never attributed to it.
- `raiderio` leaderboard and sampled Mythic+ run rows carry `logged_run_id`, Raider.IO's own id for a logged run (not a Warcraft Logs report code; null when the run was not logged).
- `simc` `hero_tree.X` conditions resolve from the decoded hero tree, so hero-tree dispatch (Blood, Brewmaster, Vengeance, Balance, Marksmanship, Affliction, Protection Warrior, ...) is followed instead of reported as runtime-only.
- `wowhead entity` and `comments` linked-entity previews add `fetch_more_truncated`, true when the page has more links than `entity-page --max-links 2000` (the preview's `fetch_more_command`) can return.
- `icy-veins` and `method` `search`/`resolve` read class and spec shorthand (`ret pally`, `bm hunter`, `frost dk`, `disc priest`) as the full names, in the query and in page titles alike, so `disc belt` still finds the "Disc Belt Guide".
- `simc priority` and `opener` report `total` and `truncated`, `inactive-actions` reports `truncated`, and `describe-build` reports `active_priority_total`, `active_priority_truncated` and `inactive_talent_branch_total`. `simc run` adds `result_lines` (the `Player:` and `DPS=` lines).
- `icy-veins search` and `resolve` find current guides missing from the stale Icy Veins sitemap (for example the current season's raid, Mythic+ and PvP pages, and the Devourer Demon Hunter guide) by reading the site-wide guide menu on a class hub page whenever the sitemap's newest entry is more than 30 days old.
- Every `icy-veins search`/`resolve` row carries `metadata.source` (`sitemap` or `site_menu`). Menu-found rows have `sitemap_lastmod: null` and a `metadata.menu_title`; `provenance` adds `site_menu_url`, plus `site_menu_warning` when the menu could not be read, in which case results fall back to the sitemap alone.
- `simc sim` reports `actor_count` and `other_actors` (each with `player` and `metrics`) for multi-actor profiles, and `profilesets` (`metric`, `result_count`, ranked `results`) for Top Gear/Droptimizer profiles. Previously only players[0] was reported.
- `icy-veins index-refresh [--max-requests N]` (default 250) crawls Icy Veins for the pages its frozen sitemap lacks, waiting at least one second between requests, or `WARCRAFT_HTTP_MIN_INTERVAL_SECONDS` when that is longer. It follows the site menu and every linked page the sitemap does not list, then re-reads the previous index's pages. It merges the result into a durable local site index (`<data root>/icy-veins/site_index.json`, page metadata only, never replaced, so past-season pages stay findable). A run stops at the first 403, 429 or Cloudflare challenge without retrying, and at the request cap, reporting `partial`, `stop_reason` and counts; the next run resumes from the recorded frontier. A blocked run keeps the index's previous `refreshed_at`, so its age warning stands, and writes nothing when it read nothing. A seed page that lists no links fails as `parse_failed` and leaves the index untouched.
- The `icy-veins` package ships a site index snapshot (243 pages from a full crawl on 2026-10-03, 147 of them missing from the sitemap), so `icy-veins search` and `resolve` find the current season's boss, dungeon and delve pages before any crawl. `icy-veins doctor` reports the index in use under `site_index` and the `index_refresh` capability.
- While the sitemap is stale, `icy-veins search` and `resolve` also rank site-index pages (`metadata.source: "site_index"`, named by the page headline) and match every indexed page on its headline (`voidspire` finds the Voidspire boss pages). Results carry `metadata.date_published` and `metadata.parent`. A renamed page is ranked once, under its new slug. Provenance adds `site_index_path`, `site_index_refreshed_at`, and `site_index_warning` when the local index is over 7 days old or the live menu links pages it lacks.
- Icy Veins content families `raid_encounter`, `dungeon_guide`, `delve_guide`, `profession`, `tier_list`, `hub` and `transmog`; old raid hubs classify as `raid_guide`, raid strategy pages whose slugs end in `-raid` (for example `orgozoa-strategy-guide-in-the-eternal-palace-raid`) as `raid_encounter`, and a spec's PvP sub-pages as `pvp`, so boss pages, professions, tier lists and hubs such as `void-assaults-hub` are now searchable and open with `icy-veins guide`. Transmog pages rank only for a query that says transmog (`penalty_transmog`).
- The `warcraft-wiki` article/api/event summary `navigation` block carries `more_available` and `fetch_more_command`, like `linked_entities`.
- `raiderio affixes [--region]` returns this week's Mythic+ affixes, and `raiderio dungeons [--expansion-id]` lists each Mythic+ season with its dungeon pool and `--dungeon` slugs; an `--expansion-id` Raider.IO has no Mythic+ seasons for (for example 12) fails `invalid_query` (exit 2) instead of returning an empty list.
- `raiderio character` returns `mythic_plus.best_runs` (Raider.IO's best run in each dungeon this season) and `best_run_count`. `recent_runs` now lists every recent run (was the first 5 of up to 10), so `recent_run_count` matches the list.
- Lorrgs, Blizzard and CurseForge responses are cached (Lorrgs metadata 12 h, rankings 30 min, loaded fights 6 h; Blizzard static 24 h, dynamic/profile 15 min; CurseForge 1 h), configurable with `LORRGS_*`, `BLIZZARD_*` and `CURSEFORGE_*` cache env vars. `provenance.cache` reports whether an answer was replayed, and each doctor reports its cache configuration.
- `simc build-harness` and `simc sim` return `disclosures`. A profile with `load_default_gear=1` (every harness) is flagged as wearing SimC's low item level default gear, so its absolute DPS is not representative.
- `method search`/`resolve` understand section words after a spec (`arcane mage talents`, `frost dk gearing`, `mw monk rotation`, `stats`, `bis`, `macros`): the class guide row's `url` and `follow_up.command` open that section (`method guide arcane-mage/talents`), with `metadata.section_slug` and the `section_query` match reason. These queries used to return nothing.
- `make icy-veins-snapshot` rebuilds the bundled Icy Veins site index from a live crawl and refuses to replace it with a partial run.
- Every `wowhead`, `method`, `icy-veins` and `warcraft-wiki` search/resolve row carries `provider` and `kind` (`guide`/`article` for the article family; the snake_case entity type on Wowhead, e.g. `transmog_set`).
- `lorrgs` spec-ranking and comp-ranking search/resolve rows carry the Lorrgs page in `url` (`https://lorrgs.io/spec_ranking/<spec>/<boss>[?difficulty=...]`, `https://lorrgs.io/comp_ranking/<boss>`); spec, boss and report rows have `url: null`.
- `warcraftlogs search`/`resolve` rows carry the report `url`, on the site the report URL names. Search data carries `total_matches` and `truncated`. Resolve data carries `candidates`, `count`, `total_matches` and `truncated`. Removed the duplicated `follow_up.provider` and `follow_up.kind` from Warcraft Logs rows; `follow_up` is now `{command, surface}`.
- `warcraft search` `merge_policy.provider_total_matches` (`{provider: total_matches | null}`), present under `--brief` too.
- `lorrgs` `spec`, `spec-spells`, `spec-ranking`, `spec-ranking-info` and `comp-ranking --spec` take any provider's spelling of a spec (`balance-druid`, `Balance Druid`, `BeastMastery`, `death-knight-frost`, `bm hunter`) and send the Lorrgs slug (`druid-balance`), which `query.spec_slug`/`query.specs` echo. On the spec routes, a value naming no one spec is still sent as typed; when Lorrgs answers it `not_found` (exit 4), `error.details.suggestions` lists the closest Lorrgs spec slugs (absent when none is close). An unknown `comp-ranking --spec` name is not an error upstream and still returns `reports: []`.
- `raiderio` `--contains-spec` and `--contains-class` accept every provider's class/spec spelling (`deathknight`, `DeathKnight`, `dk`; `BeastMastery`, `deathknight-frost`, `balance-druid`, `Frost Death Knight`); a spelling that names one spec is echoed as its class-qualified Raider.IO slug (`hunter-beast-mastery`). Raider.IO's own slugs, including bare `holy`, behave as before.
- `warcraft cooldown-packet --spec-slug` accepts any provider's spelling (`frost-death-knight`, `Protection Warrior`, `BeastMastery`) and uses the Lorrgs slug; a bare spec two classes share (`frost`) takes the player's class.
- **`provenance.cache` on every binary.** A success envelope from a command that built a cache store reports `{backend, lookups, hits, hit, all_hits, oldest_hit_age_seconds, oldest_hit_ttl_seconds}`. `hit` means some lookup was replayed from the local cache, `all_hits` means nothing came off the wire, and ages are null with the Redis backend. `warcraft` reports the aggregate over the providers it called, and each embedded provider envelope keeps its own block (`backend: "mixed"` when those providers used different backends). A missing block carries no meaning. `--fields` keeps it only when asked for (`--fields provenance.cache`). See [docs/USAGE.md](docs/USAGE.md#reading-cache-state-provenancecache).
- Wowhead item sets (tier sets such as "Battlegear of Wrath") come back from `search`/`resolve` as `entity_type: "item-set"` with a URL and the follow-up `wowhead entity item-set <id>`; `resolve --entity-type item-set` filters to them.
- `warcraft resolve` lists `provider_resolved_candidates`, every match its provider resolved at `high` that a better-ranked unresolved match kept from being the answer, each with its `next_command`. Before, such an answer (Icy Veins' arena page for `affliction warlock arena`, the wiki's `Mount` for `mount`) appeared in no hint.
- `warcraft cooldown-packet` takes phase windows from the Warcraft Logs fight's phase transitions when Lorrgs cannot serve the report. They are numbered P1, P2, ... in order, as on the Lorrgs path, so `--phase` and the top-parse comparison pick the same window. Each window carries the encounter phase's `phase_id` and `name`. `phase.source` says whether the windows came from `lorrgs` or `warcraftlogs`, and the new `sources.warcraftlogs_phase_transitions` records the lookup.

### Changed

- **Exit codes**: `2` usage (`invalid_query`, `invalid_argument`, `missing_fields`), `3` auth, `4` not found (including upstream 404), `5` network, timeout, rate limit and upstream failures, `1` everything else, on every binary. Provider-specific mappings are listed in ERROR_CONTRACT.md and each provider README.
- **Upstream HTTP failures** are `auth_failed` (401/403), `not_found` (404), `rate_limited` (429) or `upstream_error` (other statuses), timeouts `timeout`, connection failures `network_error`, instead of `http_error`, always with `error.details.status_code` and `url`. Lorrgs answers 401/403 with `not_found` (the report is private).
- HTTP clients send `User-Agent: warcraft-cli/<version>`, space requests to one host by `WARCRAFT_HTTP_MIN_INTERVAL_SECONDS` (default `0.25`) and cap `Retry-After` at 30 s. Auth state files are written 0600 in a 0700 directory, and `.env.local` discovery stops at the git root.
- Handed-over commands (`next_command`, `follow_up.command`, `fallback_search_command`, `fetch_more_command`, cooldown-packet source commands) are shell-quoted. Wowhead, Icy Veins, Method and Warcraft Wiki rows name theirs in `follow_up.command` (was `follow_up.recommended_command`) and list the others in `follow_up.alternative_commands` (was `follow_up.alternatives`), which `--compact` never truncates.
- Choosing the Redis cache backend without a URL fails naming the provider's own variables (`METHOD_REDIS_URL`, not `WOWHEAD_*`), and `doctor` prints `redis_url` without credentials.
- `warcraft` calls providers in-process. `doctor` answers offline (no Warcraft Logs auth probe) and drops `language` and `shell_fallback`.
- `warcraft search` and `resolve`: `--brief` is the small payload (was `--compact`, now only the global flag). `search` merges providers by query intent, keeps each provider's own order, caps any provider at half the page, lets the entity provider's exact-name row lead, and reports the rules in `data.merge_policy`. Both report `answered_provider_count`, `failed_provider_count` and `failed_providers[]` (with `exit_code`), and fail when no searching provider answered: with the providers' shared code, `upstream_error` (exit 5) when all failed upstream, otherwise `providers_failed` (exit 1).
- `warcraft resolve` answers with the candidate `search` ranks first, and only when that candidate's own provider resolved it and the query's intent does not rank its family down; otherwise `resolved: false` with `best_unresolved_candidate` (carrying `unresolved_reason`) and `fallback_search_command(s)`. `provider` is always `"warcraft"`, the chosen one is `data.selected_provider`, and `--limit` only sizes `--ranking-debug`. Guide queries no longer resolve to Lorrgs or Warcraft Logs spec rows. `fallback_search_command(s)` come only from providers that returned a candidate, in ranking order (`null` / `[]` when none did).
- `warcraft guild` is a Raider.IO snapshot: `data.sources.raiderio.summary.raids[]` carries every raid with its own normal/heroic/mythic world, region and realm ranks (`0` means unranked). There is no `active_raid` or `conflicts` block, and a failure keeps Raider.IO's own code. `sources.raiderio` carries `summary` and `provenance`, not the raw Raider.IO envelope (`warcraft raiderio guild` returns that).
- `warcraft cooldown-packet`, `actor-profile`, `talent-packet` and `talent-describe` exit with the failing source's code (auth 3, not found 4, network 5) instead of 1.
- `warcraft cooldown-packet` compares at the fight's own difficulty unless `--difficulty` is passed, reports `phase.requested`, and names why no top-parse comparison ran in `comparison.reason` (`no_boss_slug`, `unranked_difficulty`, `lorrgs_spec_ranking_failed`, `disabled_by_sample_limit`). For a report Lorrgs has not cached it returns the Warcraft Logs half with `--actor-id` and `--spec-slug` (`lorrgs.status: "unavailable"`). A fight the report lacks fails `fight_not_found` (exit 4, `error.details.available_fight_ids`); `actor_id_not_found`, `actor_name_not_found` and `lorrgs_fight_not_found` exit 4.
- `warcraft actor-profile` without `--fight-id` works again: it searches at most 10 of the report's fights, kills first (`query.scoped_fight_ids`, `query.fight_scope`), and fails `report_has_no_fights` or `actor_not_found` (exit 4).
- `warcraft guide-compare-query` writes under `<data root>/guide_compare/<query-slug>` (doctor's `paths.data_root`) by default (was the current directory). A provider that failed is a `provider_failed` or `guide_export_failed` row with `error {code, message}`; when every provider that contributed nothing failed outright, the run fails with their shared code (a network outage: `network_error`, exit 5) instead of `insufficient_guides`, which now lists each provider's decline reason. `--simc-build-handoff` fails `simc_handoff_failed` when every simc leg failed. Flags that leave fewer than two guide providers (a single `--provider`, or a non-retail `--expansion`) fail `invalid_argument` (exit 2) before any provider call.
- `warcraft guide-builds-simc` reports `summary.simc_handoff_status` (`ok`, `partial`, `failed`, `no_build_references`, or `all_references_excluded` when the guide had build references but none could be handed to simc), excluded builds and per-build failures, and fails `simc_handoff_failed` (exit 1) when every requested leg produced nothing.
- `warcraft guide-compare` rejects fewer than two bundles or the same bundle twice (`invalid_argument`, exit 2); a missing path is `not_found` (exit 4). `talent-describe` reports `written_packet_path` (was `packet_written_path`). Passthrough expansion refusals exit 2 with `provider: "warcraft"`.
- `wowhead` `count` is the rows returned, with `total_matches` and `truncated` beside it. `search`/`resolve` rank every row of Wowhead's suggestion response on Wowhead's own order, match whole query words, drop rows that match none, sort superseded guides down and never resolve one with high confidence; `resolve` prefers a database entity over news and events. A query that is itself a name made of follow-up words ("Soul Link") is searched whole first, and `search <Wowhead entity URL>` answers with that entity.
- `wowhead` guide sections and `guide-query` spell out inline `[spell=N]`/`[item=N]` tokens with the page's names and keep `[build]` blocks. `guide-bundle-refresh` re-exports from the bundle's recorded expansion. `dressing-room` fetches from the share URL's expansion. `entity`'s normalization version moved to `normalized.schema_version`. Entity cache entries from older versions are refetched once.
- `warcraftlogs report-player-talents` no longer runs SimulationCraft: packets are `raw_only`; validate them with `simc validate-talent-transport --build-packet` or use `warcraft talent-packet`. Damage and aura summaries return typed rows only (the raw table is behind `--include-raw`). `graphql` returns the result's own `data`.
- `warcraftlogs` typed commands report GraphQL partial errors from every request in `data.graphql_warnings`, and never cache a partial response. A report counts as finished (24 h cache, sampled cohorts) once its last event is 2 hours old. `?fight=N` report URLs are scoped like `#fight=N`.
- `warcraftlogs report-player-details` and `report-events` require `--fight-id` or a start/end window (`missing_scope`, exit 2); a fight id, encounter or difficulty the report lacks is `not_found` (exit 4, `missing_fight_ids`), and a window starting past the fight's end is `invalid_query` (exit 2), where each used to return an empty slice. Input errors exit 2 and `site_profile_mismatch` exits 3. Credential discovery no longer mutates `os.environ`.
- `warcraftlogs report-encounter-aura-compare` rows carry left/right/delta `reported_total_uptime` and `reported_total_uses`, sorted by the largest uptime change; the always-null `reported_total`/`reported_active_time` fields are gone. `boss-spec-usage` rows are keyed by class + spec + role, and `--spec-name` accepts class + spec (`'Frost Mage'`).
- `simc` identifies a bare talent export by probing every spec (healers included), with case-insensitive class and spec names; a class or spec guessed from an APL file name or talent-calc URL that the hash contradicts is ignored. It reads Wowhead `/talent-calc/blizzard/<hash>` URLs. Failure extras moved into `error.details`, and the executed argv is `data.command`.
- `simc modify-build` takes spec and hero talents by name in `--add`/`--remove`, routing each edit into its own tree, verifies the re-encoded build (`result.verified`, `result.disclosures`), and fails `encode_mismatch` when an edit did not land or something else changed. `--add` on a taken choice node is `invalid_argument` naming the `--remove` that swaps it. Missing or malformed edits are `invalid_argument` (exit 2).
- Talent transport validation compares tiered nodes by rank and rejects a rank above the maximum, a negative rank or a repeated entry; rows from two hero trees leave the packet `multiple_hero_trees`.
- `raiderio` `spec` metrics, `composition` keys and player `spec_slugs` are class-qualified (`priest-holy`); `--contains-spec` accepts both forms. `resolve` judges confidence over every candidate regardless of `--limit`. `guild`/`character` lead words are type hints only; multi-word and punctuated realms resolve. `raids` reports `freshness`.
- `warcraft-wiki` fetches `API:`/`Event:` pages by canonical title first and accepts a search fallback only when every query word matches its title (a miss is `not_found`, exit 4). `resolve` is confident only when the top title covers the whole query, and a leading family word stays when a page is titled with the whole query (`class hall`). `event` pages fill `reference.arguments`.
- `lorrgs zones` returns `data.zones`. `user-report-fights` without a fight exits 2 (`missing_fight`).
- `icy-veins search`/`resolve` keep a guide only when it contains the whole query or every query word (or a word names its family), read `+` as `plus`, send a spec query to that spec's `...-pve-<role>-guide` (a hunter spec never to its pets page), and rank a page updated more than a year before the newest one down (`penalty_stale_page`), so a past season's guide sorts below the current one. `method` searches `mythic+`/`m+` as `mythic dungeon`.
- `icy-veins` and `method` `guide-query` answer with one shape (kind `guide_query`, `bundle`, `guide`; was `bundle_query` on Icy Veins and `output_dir` on Method), and `method guide-export` returns `files` instead of the whole `manifest`. Both answer bad bundles the same way: missing `not_found` (4), a file `invalid_argument` (2), unreadable `invalid_bundle` (1); a section whose title matches the query ranks above sections that only mention it. A blank `search`/`resolve` query is `invalid_query` (exit 2).
- `blizzard` `realm` and `character` accept display names and either slug spelling (`Mal'Ganis`, `Tarren Mill`); flag-validation failures exit 2. `blizzard` (us/eu/kr/tw) and `curseforge` payloads report `provenance.verified: true`. `curseforge` `data.changelog` names the file's `display_name` and `release_type`.
- `raidbots` rejects an unparseable report reference with `invalid_report_ref` (exit 2); quick-sim reports with several actors carry `actor_count` and `other_actors`.
- A malformed guide, tool or page reference is a usage error: `invalid_guide_ref` (`icy-veins`, `method`), `invalid_tool_ref` and `invalid_ref` (`wowhead`, and the `warcraft` talent routes that pass them through) exit 2 (was 1).
- `warcraft` reports a composed provider failure without its own error code as `provider_failed` (was `provider_command_failed`).
- `warcraft cooldown-packet` without Lorrgs reads the selected fight's Warcraft Logs roster (`report-player-details --fight-id`, source key `sources.warcraftlogs_report_player_details`) for the player's name and class: an actor who is not in that fight fails `actor_id_not_found` (exit 4) instead of returning zero casts, and a `--spec-slug` of another class than the player's fails `invalid_query` (exit 2).
- `wowhead entity`, `entity-page` and `comments` linked entities include the page's relation tabs (a zone's NPCs, quests and objects; a faction's members) with `source_kind: "listview"` and the tab id in `listview`.
- `warcraftlogs report-player-details`/`report-encounter-players` `class_spec_identity.confidence` is `high` for a fight-sourced single spec (was `none`). `auth login`/`pkce-login` no longer store the unused OAuth refresh token, and the token-exchange output drops `token.has_refresh_token`.
- `simc priority`, `opener`, `inactive-actions` and `describe-build` follow the build past auto attacks, interrupts, potions, trinkets, racials and helper lists into the list where its rotation lives (Retribution -> generators, Arcane -> spellslinger/sunfury, Beast Mastery -> st); `apl-intent`, `apl-intent-explain`, `analysis-packet` and `apl-branch-compare` use the same focus-list resolution.
- `simc` APL analysis commands report a bad build input with decode-build's codes (`unsupported_build_reference`, `invalid_query`, exit 2) instead of `<command>_failed` (exit 1). `data.build.enabled_talents` (and `left`/`right` in `apl-branch-compare`) is a list of talent tokens with `enabled_talent_count` beside it (was an int). A relative APL path is read from the current directory when the file exists there, otherwise from the SimC checkout.
- `simc` talent tokens follow SimC's tokenizer (hyphens and commas dropped): `decode-build`, `enabled_talents` and `talent_sources` print `antimagic_zone`, `invoke_chiji_...`, and `modify-build`/`apl-prune` inputs match them. - `blizzard character` sends the character name as one URL path segment, so a `/`, `?` or `#` in the name can no longer reach another Blizzard endpoint. A name made only of dots is `invalid_query` (exit 2).
- A provider `resolve` that matched nothing no longer hands over a `fallback_search_command` (the same search would come back empty).
- An integer argument beyond 64 bits (`wowhead entity item 99999999999999999999`) no longer turns the answer into `internal_error`. The envelope prints with the provider's real error.
- `simc run` and `simc sim` fail `invalid_query` (exit 2) when SimC finds nothing to sim (an empty profile) instead of reporting `completed`, and fail `not_found` (exit 4) for a profile path that is not a file.
- `raidbots explain-input` rejects text with no SimC `key=value` line (`invalid_query`, exit 2) instead of calling it an Advanced Sim.
- `simc sim` and `raidbots explain-input` fail `invalid_query` instead of waiting forever when they would read a terminal on stdin.
- `--expansion ""` is rejected as an unknown expansion (`invalid_argument`, exit 2) by `warcraft` and `wowhead` instead of silently switching on retail filtering.
- `icy-veins index-refresh` with a data directory it cannot write (`XDG_DATA_HOME` pointing at a file) now fails as `invalid_data_dir` (exit 1) before it fetches anything, with the index path in `error.details.path`. Before, it failed as `internal_error: NotADirectoryError` after the whole crawl. A write that fails after the crawl (a full disk) is also `invalid_data_dir`.
- `icy-veins`, `method` and `warcraft-wiki` `resolve --limit` help said 'Maximum candidates to inspect'. It now says the limit only trims the list, and that ambiguity is judged over every match (for the wiki, over every hit fetched, 5 x limit and at least 25).

## [0.3.0] - 2026-05-08

### Added

- `view-private-reports` scope is now first-class alongside `view-user-profile`. `auth login`, `auth pkce-login`, `auth status`, `auth token`, and `doctor` decode the access token's JWT body to surface `scopes.has_view_private_reports`, and `scope_warning` walks you through what to re-auth for. WCL's token response omits the granted-scope list, so reading the JWT is the only reliable way to know what the user actually has.
- `report-events` now appends a hint when a narrowed slice still resolves to `events.data: null`, pointing at the `--data-type` flag (`casts`, `damage-done`, `healing`, …) rather than surfacing a bare null.

### Changed

- Every WCL command surfaces partial-error context as `notes` and `graphql_warnings` in JSON output via a centralized `_emit(client=client)` path.
- `GuildAttendance` no longer selects `Zone.frozen` — that field was nulling out for real guilds (e.g. `gn / us-malganis`) and tripping the partial-error path. Pagination, rosters, and zone identity continue to flow.

### Fixed

- Private and guild-stealth typed encounter analytics now return populated rows. `v0.2.0` routed authenticated traffic to `/api/v2/user`, but the parsers still expected the legacy `report.table.entries` shape; live WCL responses use `report.table.data.entries` (and `data.auras` for buffs). `report-encounter-damage-source-summary`, `report-encounter-damage-target-summary`, `report-encounter-damage-breakdown`, and `report-encounter-aura-summary` were silently returning zero rows on real reports despite passing the fixtures. The parser now drills into the `data` wrapper.
- WCL `{ "data": ..., "errors": [...] }` partials are tolerated. The client uses a recursive useful-data check: if any leaf value (or non-empty list) is populated at any depth, the response flows through with the error list captured as `last_warnings`. If every leaf is null, the original GraphQL error is raised so users see the real failure rather than a misleading `not_found`.
- `null` GraphQL variables are pruned at the wire. WCL rejects `null` variable values with `Internal server error` instead of treating them as omitted, so `character-rankings ... --spec-name <slug>` and similar flag-driven calls were 500'ing whenever an optional flag was unset alongside a set one. Cache keys use the pruned variable set so cache identity stays stable across `null`/omitted callers.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --scope view-private-reports \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-private-reports` continue to work for public queries; `auth status` reports the missing scope.

## [0.2.0] - 2026-05-06

### Added

- `view-user-profile` scope is now first-class. `auth login`, `auth pkce-login`, `auth token`, `auth status`, and `doctor` expose `scopes.granted`, `scopes.requested`, `scopes.has_view_user_profile`, and a `scope_warning` when the scope is missing. WCL requires this scope to establish a user identity; without it, `userData.currentUser` resolves to null and ACL checks fall through to anonymous.

### Changed

- WCL routes report and guild GraphQL queries through `/api/v2/user` whenever a non-expired user token is saved. Previously every query went to `/api/v2/client` with the client-credentials token, so private and guild-stealth reports returned "permission denied" no matter how many times the user re-authenticated. Cache payloads are namespaced by endpoint family so client- and user-API responses can never collide on disk.
- Public-API probes stay pinned to the client endpoint via a new `force_client=True` opt-out on `rate_limit()` and `probe_live_public_api()`. Without this, broken client credentials could be masked by a working user token.

### Fixed

- `load_provider_auth_state` returns `None` on `OSError` / `JSONDecodeError`, matching the contract `provider_auth_status` already followed. Corrupt or hand-edited state files no longer crash the CLI.
- `auth token` only emits `scope_warning` when there's actually a saved user token; fresh setup, logged-out, and corrupt-state cases now report `scope_warning: null`.

### Upgrading

```bash
pip install -U -e '.[dev]'
warcraftlogs auth login \
  --scope view-user-profile \
  --redirect-uri http://localhost:8787/callback
```

Existing tokens issued without `view-user-profile` continue to work for public queries; `auth status` reports the missing scope.
